`@kanzo-tech/llm` is what `@kanzo-tech/ai` talks to a model through: every model call the library
makes passes through it, once. It has no React in it.

```bash
pnpm add @kanzo-tech/llm ai
```

```ts
import { localModel } from "@kanzo-tech/llm/local";

// The model runs in the page, on WebGPU: no key, no server, nothing leaves the browser.
const model = localModel("Qwen3-4B-q4f16_1-MLC");
```

**The model is in the page.** The platform's [Tasks](/docs/ai/tasks) are built for one: a small
model filling a small artefact that a schema or a grammar holds it to, checked by oracles — so no
provider, no key and no gateway stand between a person and the answer ([why](/docs/design/tasks)).
`localModel` is a `LanguageModel`, so everything above it — `stream`, `ToolLoopAgent`, `Chat`,
`Assist` — takes any other one the same, [the double](#a-model-double) included.

## One copy of the SDK

`ai` is a **required** peer, not an optional one and not a dependency. There is nothing here without
it — that is what this package is — and installing it once is the point: `@kanzo-tech/ai`'s
components and the host's own agent must see the same `UIMessage`, the same agent and the same
transport. Two copies of the SDK are two type universes whose messages do not assign to each other,
and the error that reports it names neither copy.

**Nothing of the SDK passes through this package.** `ToolLoopAgent`, `tool`, `jsonSchema`, `Output`,
`DirectChatTransport`, `LanguageModel`, `UIMessage` and the rest are imported from `ai` by name, as
every package here imports them: a host has `ai` installed anyway, so passing them through was a
second way to write one import ([why](/docs/design/tasks#where-each-dependency-lives)). What is here is what the
SDK lacks — the two doors every model call the library makes goes through, [`stream`](#stream) and
[`generate`](#generate), each asking once; [`LlmError`](#llmerror); `ModelLoad`; and, on subpaths
whose peers are optional, the model and its double.

## `localModel`

`@kanzo-tech/llm/local` runs one on WebGPU, through [WebLLM](https://github.com/mlc-ai/web-llm) and
the AI SDK provider [`@browser-ai/web-llm`](https://www.npmjs.com/package/@browser-ai/web-llm) —
both optional peers, reached only from this subpath, so a host that runs no model in the page
installs neither:

```bash
pnpm add @browser-ai/web-llm @mlc-ai/web-llm
```

```ts
import { localModel, localProvider, setLocalProvider } from "@kanzo-tech/llm/local";

// Once, at the composition root, before anything asks a model.
setLocalProvider(
  localProvider({
    baseURL: "/models",
    worker: new Worker(new URL("./model.worker.ts", import.meta.url), { type: "module" }),
  }),
);

const model = localModel(); // the first model /models serves; localModel(id) for another
```

```ts
// model.worker.ts — the worker's whole script
import { serveLocalModel } from "@kanzo-tech/llm/local";

serveLocalModel();
```

**A model is resolved by id through one provider registry.** `localModel(id?)` asks it: the model a
test registered for that id, else the provider the host set with `setLocalProvider`, else WebLLM's
own prebuilt list — the AI SDK's `customProvider` with its `fallbackProvider`, kept on the page as
OpenTelemetry keeps its global provider ([why](/docs/design/testing#a-model-is-resolved-through-one-registry)).
`localProvider({ baseURL, worker })` is WebLLM's provider, configured with where its models are
served from and the worker its engine runs in — a `LocalProviderSettings`, both optional. Without an id, `localModel()` asks the
first model served. It is a `LanguageModel`, so `stream`, `ToolLoopAgent` and `Chat` run over it
unchanged. It makes one engine per model per page — two would be two copies of the weights in the GPU's memory — and
lifts `<think>` into reasoning — Qwen3 and DeepSeek write theirs inline, and [`Chat`](/docs/ai/chat) folds it away. Without WebGPU a call fails as an `LlmError`
coded `llm/unavailable` with `data.reason` `"webgpu"`, before anything is downloaded or fetched. The weights are
downloaded on the first call and cached by the browser, which is asked once to persist what it stores
for the page (`navigator.storage.persist()`), so a model is not evicted under pressure. A structured answer (`Output.object`) is
decoded against its schema; a tool is described in the prompt and parsed out of the model's text, so a
small model can write a call that does not parse. Why the platform is moving to models in the page,
and why its Tasks use no tools, is [Tasks](/docs/design/tasks).

**Serve the models yourself, and load one before it is asked.** Without `baseURL` the provider is
WebLLM's prebuilt list and the weights come from Hugging Face. With it, the page serves exactly what
`<baseURL>/app-config.json` lists, from your own origin, so it reaches no third party. That file is
**WebLLM's own `AppConfig`**, as `@mlc-ai/web-llm` declares it, handed to WebLLM untranslated — a
`model` or `model_lib` written relative is resolved against `baseURL`, because WebLLM reads both from
its worker, where a relative URL means another place:

```json
{
  "model_list": [
    {
      "model": "Qwen3-4B-q4f16_1-MLC/resolve/a5c9fab855e3ccbdfed2e7e69683d75f30332161/",
      "model_id": "Qwen3-4B-q4f16_1-MLC",
      "model_lib": "lib/v0_2_86/Qwen3-4B-q4f16_1_cs1k-webgpu.wasm",
      "overrides": { "context_window_size": 4096 }
    }
  ]
}
```

It is a static file beside the shards, written by whatever downloads them, so a plain file server
serves it. WebLLM reads the weights under `model` as Hugging Face lays a revision out: a `model` that
names no `resolve/<revision>/` is read under `resolve/main/`. The host's code names no model and no library version: a new model is a line here.
Everything WebLLM's prebuilt record says of a model — its `overrides`, its VRAM, the GPU features it
needs — is the listing's to say. A listing that is missing or lists nothing, and an id it does not
list, are `llm/unavailable` with `data.reason` `"unserved"`.

```ts
// When the screen that will ask opens: the download starts now, not on the first question.
void loadLocalModel();
```

`loadLocalModel(id?)` resolves when the engine is ready, on the same engine `localModel` answers
with, and rejects as a call would.

*Held by* `packages/llm/src/local.test.ts`, "serves every model its app-config.json lists, in order,
the first when no id is asked, with WebLLM's config handed on as written", "is unserved when the
listing is missing, lists nothing, or does not list the id asked", "loads ahead of the first call, on
the one engine, and asks once for the storage to persist".

**Where the load stands is read, not handed to a callback.** `localModelLoad(id)` answers a
`ModelLoad` — `{ state: "idle" }` until something loads or asks the model, `{ state: "loading",
progress, text }` with WebLLM's progress from 0 to 1 and its words, then `{ state: "ready" }` or
`{ state: "failed", error }` — whichever screen started it, and `watchLocalModel(id, listener)` says
when it changes. The value is the same object until it changes, so it is a snapshot React can hold,
and [`ModelBadge`](/docs/ai/guided#modelbadge) draws it:

```tsx
const load = useSyncExternalStore((l) => watchLocalModel(undefined, l), () => localModelLoad());
<ModelBadge load={load} onRetry={() => void loadLocalModel()} />
```

`ModelLoad` is on `@kanzo-tech/llm` rather than this subpath because it is not WebLLM's shape: a
host whose model is fetched some other way reports the same four states, and `ModelBadge` imports
no optional peer to read them. An `onProgress` setting was the way in before, and every host that
used it kept a store of its own beside it so that a second screen could read what the first had
started; the store is here now, once.

*What would reverse it:* a host that needs every progress tick as an event — a log, a measurement —
which a snapshot coalesces. Then a listener is handed the value it changed to.

*Held by* `packages/llm/src/local.test.ts`, "hands WebLLM the worker, and reports the load in
WebLLM's words to whoever watches it"; "reports a load that cannot happen as failed, with what
stopped it".

**A call can hold the model to a grammar.** `providerOptions: { kanzo: { grammar } }`, an EBNF
string (`LocalCallOptions`), reaches WebLLM's engine as `response_format: { type: "grammar" }`, and
every token the model writes is one the grammar allows: what is not in it cannot be decoded. The AI
SDK's WebLLM provider passes a JSON Schema and nothing else, so `localModel` hands a grammar to the
engine itself. A Task whose artefact is text in a language declares it ([Tasks](/docs/ai/tasks)); a
model that is not local ignores the option, and the Task's oracles judge what it wrote the same.

*Held by* `packages/llm/src/local.test.ts`, "holds the model to a grammar a call passes, on the engine
itself".

## `stream`

```ts
stream(options: StreamOptions): Stream

interface StreamOptions {
  model: LanguageModel;          // localModel(…)
  system?: string;
  prompt: string;
  output?: Output;               // Output.array(…) or Output.object(…); plain text when omitted
  abortSignal?: AbortSignal;
}

interface Stream {
  text: AsyncIterable<string>;     // the answer as it is written
  elements: AsyncIterable<E>;      // each element of an Output.array, once it is whole
  partial: AsyncIterable<P>;       // an Output.object as it grows
}
```

**The one door to a model's answer outside a conversation** — a field's continuation, a strip of
candidates, anything that asks once and reads what comes back. Read one of the three, once: they
are views of the same request.

```ts
for await (const { text } of stream({ model, prompt, output: Output.array({ element }) }).elements) {
  offered.push(text);
}
```

- **A failure throws, once the stream ends.** The SDK reports a failed stream to `onError` and then
  ends it as if it had finished, so a refused call reads as a model with nothing to say. Each
  reading rethrows what was reported, whole: a page that cannot run the model as `LlmError`
  `llm/unavailable`, anything else as the model threw it.
- **Never retried.** A model that failed on this device fails the same way asked again, and each
  attempt is a whole generation the person waits through.

A caller of the library never reaches for `streamText` instead: the raw call is the one that passes a
refusal off as a short answer, and two ways to one request are one too many. A
conversation is the other door — `ToolLoopAgent` behind `useAgentChat` — and it hands over what was
thrown itself.

*What would reverse it:* a caller that needs something of `streamText` that `stream` cannot pass —
tools in a single request, or a reading other than these three. Then the option goes on
`StreamOptions`; the raw call still does not come back.

## `generate`

```ts
generate(options: GenerateOptions): Promise<{ text: string; output: O }>

interface GenerateOptions extends StreamOptions {
  providerOptions?: ProviderOptions; // { kanzo: { grammar } } holds localModel to a grammar
}
```

**The same door, for an answer read whole** — what a [Task](/docs/ai/tasks) asks for, since its
oracles judge the artefact entire. It is `generateText` asked once, as `stream` is: a refusal rejects
with what the model threw, whole, and is never retried. A Task's own repair loop is the only second
attempt, and it carries what the oracles found; a retry of the same prompt on the same device carries
nothing.

Every model call the library makes goes through one of the two doors.

*What would reverse it:* a model the page reaches over the network again — then a silence has a
bound and a limit a name, and both go on this one door, never on `Assist`, `Chat` or a Task above
it.

*Held by* `packages/llm/src/generate.test.ts`, "never retries a refused call";
`packages/ai/src/task/task.test.ts`, "asks once: an error the SDK would retry is the failure, not a
retry after it".

## `LlmError`

```ts
class LlmError extends Error {
  code: "llm/unavailable";
  data: { reason?: string };   // "webgpu": the browser has none; "unserved": the page serves no such model
}
```

The one failure this package names: the model cannot answer here. A host branches on `error.code`,
and [`Chat`](/docs/ai/chat) draws the code with the message. Anything else a model throws reaches the
caller as it was thrown.

## A model double

```ts
import { scriptedModel } from "@kanzo-tech/llm/testing";
import { promptOf } from "@kanzo-tech/testing";

const model = scriptedModel({
  turns: [
    { when: "How many", once: true, reply: { tool: "count", input: { of: "Laureate" } } },
    { reply: { text: "There are **4**." } },
  ],
});
```

**`@kanzo-tech/llm/testing` is the one model double**: `scriptedModel(script)` is the AI SDK's
`MockLanguageModelV4`, from `ai/test`, answering from a script of turns, so `Assist`, a
`ToolLoopAgent`, `Chat` and a Task run unchanged over it, and every call is recorded on it as the SDK
records one (`doStreamCalls`, `doGenerateCalls`; `promptOf(call)`, from `@kanzo-tech/testing`, flattens what a call was told). The
script is a `ModelScript`, [`@kanzo-tech/testing`'s](/docs/testing#a-model-double) — each call answered
by the first turn whose `when` its prompt contains, a reply as text, an object, a tool call, a failure
or a call that hangs, a `pace` for a recording — because an end-to-end test registers the same script
with `playwright(page, { models })`, which registers **a provider for that id** in `/local`'s registry,
answering from the script with the same answering `scriptedModel` wraps (`scripted`, from
`@kanzo-tech/testing`). `localModel` resolves it as it resolves any provider; `/local` names no test
and imports nothing of the double.

In a unit test, `turns` may be a function of the call instead — an `AnsweredScript`, whose `turns` are `(call, index) => reply`, `call` a `ModelCall`, the AI SDK's call options — where the
answer is computed — as a recording does that recognises a question it was not given word for word.
Every example and showcase on this site runs with no network over this double, with a `pace`, so a
reader sees an answer arrive.

`@kanzo-tech/testing` is an optional peer, for the script and its answering; `ai/test` is part of `ai`.

*Held by* `packages/llm/src/testing.test.ts`, "answers each call with the first turn whose words its
prompt holds, and a once turn only once"; `packages/llm/src/local.test.ts`, "answers from the script
registered for its id, records the prompt, and never reaches WebLLM".
