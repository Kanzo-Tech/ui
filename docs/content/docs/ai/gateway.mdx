[`@kanzo-tech/llm`](/docs/ai/llm) names a model by alias behind a gateway. `services/ai/`, in this
repository and under the same release tag, is that gateway: [agentgateway](https://agentgateway.dev),
which holds the providers' keys, maps each alias to an upstream, speaks OpenAI's chat-completions
protocol whatever the upstream speaks, and trusts the same realm as everything else.
[Each capability ships both halves](/docs/design/services).

## Two aliases

An application names an **alias**, never a provider:

| Alias | For |
| --- | --- |
| `chat` | conversations and agents — [`Chat`](/docs/ai/chat), a `ToolLoopAgent` |
| `complete` | short completions asked on every pause in typing — [`Assist`](/docs/ai/assist)'s ghost text and suggestions |

Which upstream answers each one is the gateway's **profile**, so the same `gateway("chat")` runs on
a laptop's GPU in development and on a provider in production. Changing models is an edit to the
profile, not a release of every application that calls it.

## The token is the credential

```text
browser ──▶ the application's server (BFF) ──Bearer <token for the gateway, one organization>──▶ gateway ──▶ upstream
```

The browser never holds a credential for the gateway. It calls its own application's route — the
`baseURL` it hands `createGateway` — and that server exchanges the user's access token for one the
gateway accepts, and forwards. The gateway then checks three things, all from the token and none
from a key of its own:

- **It was signed by the realm** (`issuer`, keys fetched from the realm) **and issued for the
  gateway** (`aud` names the gateway's audience).
- **It names exactly one organization.** A sign-in asks for `organization:*`, every membership at
  once, and a request charged to all of them is charged to none. The server asks Keycloak for
  `organization:<alias>` in the exchange; a token for every membership is refused with 403, and an
  organization the person does not belong to never reaches the token.
- **That organization is under its budget**, when the deployment set one.

The exchange is [OAuth 2.0 Token Exchange](https://www.rfc-editor.org/rfc/rfc8693) as Keycloak
implements it ([standard token exchange](https://www.keycloak.org/securing-apps/token-exchange)):
the application's server presents the access token it holds and asks for the gateway's audience and
one organization's scope.

## What the gateway keeps

Every request is written to its database: who asked (`sub`), for which organization, the alias, the
tokens in and out, and their cost when the deployment prices its models. That table is the spend
report — per person and per organization — and it is plain SQL.

## Run it

From `services/ai/`, beside the identity service it trusts:

```sh
docker compose -f ../auth/compose.yml -f compose.yml up -d --wait
```

The gateway answers on `http://localhost:4000`. Its configuration is `gateway.yaml` beside the
compose file, and in development it serves both aliases from open models through **Docker Model
Runner**, on the host's GPU — Docker Desktop 4.40 or later, with Model Runner turned on. Compose
declares the models and points the gateway at them. The first `up` pulls them, **about 6.5 GB**;
after that the loop is offline and costs nothing.

An application's own compose includes `services/auth/compose.yml` and `services/ai/compose.yml` the
way it includes [the identity service](/docs/auth/service#include-it-from-an-application), from a
checkout pinned to the release of its packages. The containers are `ai-gateway` and `ai-postgres`,
so nothing of the application's collides with them. The gateway fetches the realm's keys at
`http://keycloak:8080` inside that network; until Keycloak answers it exits, and compose starts it
again.

## Deploying

`services/ai/modules/gateway` runs the gateway and the Postgres its request log is kept in as Swarm
services on a network the deployment owns; applications on that network reach it at its `url`
output. The module takes `gateway.yaml` as it is and puts the deployment's models in place of the
development ones. The deployment passes what is its own:

- **`profile`** — which upstream answers each alias: YAML with one key, `models`, in agentgateway's
  [`llm.models`](https://github.com/agentgateway/agentgateway/blob/v1.6.0/schema/config.md) shape. **A production profile
  is the deployment's**, not this repository's. The config is named by its hash, so changing it
  rolls the gateway and no application changes.
- **`upstream_keys`** — env name to key, for every upstream the profile names; the profile reads
  them as `$NAME`.
- **`issuer`** — the realm, as its tokens say it — and **`jwks_url`** when the gateway reaches
  Keycloak by another address. **`audience`** is the gateway's client in the realm, `ai-gateway`
  unless it is given another.
- **`tokens_per_hour`** — optionally, how many tokens each organization may spend an hour, input
  and output together. Null is no budget.

```hcl title="infra/ai.tf"
module "ai_gateway" {
  source          = "git::https://github.com/Kanzo-Tech/ui.git//services/ai/modules/gateway?ref=<release>"
  network         = docker_network.edge.name
  issuer          = "https://auth.example.com/realms/kanzo"
  jwks_url        = "http://keycloak:8080/realms/kanzo/protocol/openid-connect/certs"
  tokens_per_hour = 200000
  upstream_keys   = { ANTHROPIC_API_KEY = var.anthropic_api_key }
  profile         = <<-YAML
    models:
      - name: chat
        provider: anthropic
        params: { model: <a capable model>, apiKey: $ANTHROPIC_API_KEY }
      - name: complete
        provider: anthropic
        params: { model: <a small, fast model>, apiKey: $ANTHROPIC_API_KEY }
  YAML
}
```

<Callout type="warn">
**The budget is counted in the gateway's memory.** It is a token bucket per organization, refilled
every hour, and a restart refills it; the module runs one replica so there is one bucket. A budget
that must survive restarts, or be shared by replicas, is agentgateway's remote rate limit — Envoy's
rate-limit service and a store beside it — which this module does not run.
</Callout>

**The image is pinned by digest**, in the compose file and in the module alike. The gateway holds
every provider's key: move the pin deliberately, to a release that has been out for a few days,
never by tag.

## Timeouts

`gateway.yaml` gives an upstream 20 s to start answering and 20 s between chunks once it has. Both
are under [the client's 30 s bound on silence](/docs/ai/llm), so a hung upstream is ended at the
gateway, where it is logged, before the page gives up on it.
