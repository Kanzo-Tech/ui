## Usage

```tsx
import {
  ContextMenu,
  ContextMenuContent,
  ContextMenuItem,
  ContextMenuSeparator,
  ContextMenuShortcut,
  ContextMenuTrigger,
} from "@kanzo-tech/ui";
```

```tsx
<ContextMenu>
  <ContextMenuTrigger asChild>
    <div>Right-click here</div>
  </ContextMenuTrigger>
  <ContextMenuContent>
    <ContextMenuItem value="edit">Edit</ContextMenuItem>
  </ContextMenuContent>
</ContextMenu>
```

This is `Menu` with a context trigger — the sub-components are the same parts under different
names, so anything true of `MenuItem` is true of `ContextMenuItem`. The trigger positions the
menu at the pointer rather than against an anchor, and gets `cursor-default` so a right-
clickable region does not advertise itself as text.

A context menu should never be the only route to an action: right-click is not reachable by
keyboard on its own, so mirror the items in a toolbar `Menu`.

## Anatomy

```text
ContextMenu
├── ContextMenuTrigger
└── ContextMenuContent
    ├── ContextMenuGroup
    │   └── ContextMenuItem
    │       └── ContextMenuShortcut
    ├── ContextMenuSeparator
    └── ContextMenuSub
        ├── ContextMenuSubTrigger
        └── ContextMenuSubContent
```

## API Reference

Every part forwards to its `Menu` counterpart unchanged — see the
[Menu API reference](/docs/components/menu#api-reference). `ContextMenuItem` takes the same
`variant` prop, and `ContextMenuGroup` the same `heading`.
