<Callout type="info">
**One menu, two triggers.** Use the default `MenuTrigger` when a visible control opens it
(a button, an avatar, a "⋯"); use the [context trigger](#context-trigger) when the thing you
open from is a *region* you right-click. Everything on this page applies to both.
</Callout>

<Callout type="info">
**A menu holds commands, not a value.** If closing the surface leaves state behind, you wanted a
listbox — [`Select`](/docs/forms/select) or [`Combobox`](/docs/forms/combobox). See
[the rule](/docs/forms/controls#a-menu-is-a-command-a-listbox-is-a-value).
</Callout>

## Usage

```tsx
import {
  Menu,
  MenuContent,
  MenuItem,
  MenuSeparator,
  MenuShortcut,
  MenuTrigger,
} from "@kanzo-tech/ui";
```

```tsx
<Menu>
  <MenuTrigger asChild>
    <Button variant="outline">Actions</Button>
  </MenuTrigger>
  <MenuContent>
    <MenuItem value="edit">Edit</MenuItem>
    <MenuItem value="delete" variant="destructive">Delete</MenuItem>
  </MenuContent>
</Menu>
```

Every item needs a `value` — it is the id the menu reports through `onSelect` and the key
typeahead navigation matches against.

## Anatomy

```text
Menu
├── MenuTrigger
└── MenuContent                 (portal + positioner)
    ├── MenuGroup

    ├── MenuRadioGroup
    │   └── MenuRadioItem
    ├── MenuSeparator
    └── MenuSub
        ├── MenuSubTrigger
        └── MenuSubContent
```

## Context trigger

`ContextMenu` is this same menu with one part swapped: a `ContextMenuTrigger` that opens on
right-click at the pointer, instead of a `MenuTrigger` anchored to a control. Every other part
is the Menu part under a `ContextMenu*` name, so anything true of `MenuItem` is true of
`ContextMenuItem`.

<ComponentPreview componentName="context-menu" />

```tsx
import {
  ContextMenu,
  ContextMenuContent,
  ContextMenuItem,
  ContextMenuTrigger,
} from "@kanzo-tech/ui";
```

```tsx
<ContextMenu>
  <ContextMenuTrigger asChild>
    <div>Right-click here</div>
  </ContextMenuTrigger>
  <ContextMenuContent>
    <ContextMenuItem value="edit">Edit</ContextMenuItem>
  </ContextMenuContent>
</ContextMenu>
```

Reach for it when the target is an area rather than a control — a row, a canvas, a file in a
tree. But right-click is not reachable by keyboard on its own, so a context menu should never be
the only route to an action: mirror the items in a toolbar `Menu`.

## API Reference

### Menu

| Prop | Type | Default |
| --- | --- | --- |
| `positioning` | `PositioningOptions` | `{ placement: "bottom-end" }` |
| `lazyMount` | `boolean` | `true` |
| `unmountOnExit` | `boolean` | `true` |

Extends `React.ComponentProps<typeof ArkMenu.Root>`.

### MenuItem

| Prop | Type | Default |
| --- | --- | --- |
| `variant` | `"default" \| "destructive"` | `"default"` |

`MenuQuickItem` is the same item stacked vertically with a larger icon, for the grid-style
"quick action" rows.

### MenuGroup / MenuRadioGroup

| Prop | Type | Default |
| --- | --- | --- |
| `heading` | `string` | — |

### Notes

`MenuContent` caps itself at a fixed `max-h-96` rather than the floating-ui available-height
variable. Clamping to the measured space feeds the element's own resize back into the
positioner — content shrinks, the scrollbar toggles, the available space changes, recompute —
and that loop hard-freezes the tab. A fixed cap is decoupled from the measurement.

### ContextMenu parts

Each `ContextMenu*` part forwards to its `Menu` counterpart unchanged — `ContextMenuItem` takes
the same `variant`, `ContextMenuGroup` the same `heading`. Only the trigger differs.
