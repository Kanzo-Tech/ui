title: Controls

---

Every control goes inside a [`Field`](/docs/forms) the same way, so there is no per-control API
to learn. This page is the index: find the control you need by what it captures, then follow the
link for its own page.

<Callout type="info">
**The naming rule that explains half of these.** Where you see both a `kebab-case` and a
`PascalCase` name (`input` / `TextField`, `password-input` / `SecretField`,
`date-picker` / `DateField`), the lowercase one is the **vendored primitive** — the compound
with all its parts exposed — and the PascalCase one is **our pre-assembled convenience** built
on it. Default to the PascalCase one; drop to the primitive when you need to rearrange the parts.
</Callout>

## Text

| Control | What it is | Reach for it when |
|---|---|---|
| [`Input`](/docs/forms/input) | The bare text-input primitive. | You are composing something custom on top. |
| [`TextField`](/docs/forms/text-field) | `Input` plus `size` and `iconStart` / `iconEnd` adornments. | The everyday single-line field. |
| [`NumberField`](/docs/forms/text-field) | Numeric entry with stepper semantics. | A quantity, a count, a price. |
| [`Textarea`](/docs/forms/textarea) | Multi-line text. | A description, a note, free text. |
| [`InputGroup`](/docs/forms/input-group) | An input flanked by addons — a prefix, a unit, a button. | The value needs an affix or an inline action. |

## Choice

| Control | Options | Type to filter? | Reach for it when |
|---|---|---|---|
| [`NativeSelect`](/docs/forms/native-select) | few | no | Short lists — it uses the OS picker, best on mobile. |
| [`Select`](/docs/forms/select) | few–many | no | You need custom option rendering: icons, descriptions, groups. |
| [`Combobox`](/docs/forms/combobox) | many | **yes** | Long lists, or free-text entry. Supports multiple selection. |
| [`RadioGroup`](/docs/forms/radio-group) | few | — | One of a few, all visible at once. |
| [`CardRadioGroup`](/docs/forms/card-radio-group) | few | — | One of a few, where each option needs an icon or a description. |
| [`SegmentGroup`](/docs/forms/segment-group) | 2–4 | — | A compact inline switch. Radio semantics, segmented look. |

Rule of thumb: under ~7 options, `NativeSelect`; over ~15, `Combobox`; `Select` in between when
options need to look like more than plain text.

## Boolean

| Control | What it is | Reach for it when |
|---|---|---|
| [`Switch`](/docs/forms/switch) | Reads as on/off. | A setting that takes effect immediately. |
| [`Checkbox`](/docs/forms/checkbox) | Reads as included/excluded, with a third `indeterminate` state. | A value submitted with the form. |
| [`CheckboxGroup`](/docs/forms/checkbox) | One value array across several checkboxes. | Related checkboxes you submit together. |

## Value

| Control | What it is | Reach for it when |
|---|---|---|
| [`Slider`](/docs/forms/slider) | A value or range on a track. | A bounded number where the range matters more than the digit. |
| [`DateField`](/docs/forms/date-field) | A date input with a calendar popover, assembled. | Picking a date in a form. **Start here.** |
| [`DatePicker`](/docs/forms/date-picker) | The compound date primitive. | You need to rearrange the trigger, content or calendar. |
| [`Calendar`](/docs/forms/date-picker) | The month grid on its own. | An always-visible calendar, not a form value. |
| [`ColorPicker`](/docs/forms/color-picker) | Area, hue and hex, with preset swatches. | Picking a colour. |

## Credentials

| Control | What it is | Reach for it when |
|---|---|---|
| [`PasswordInput`](/docs/forms/password-input) | A password input with a reveal toggle. | **Entering** a password — sign-in, sign-up. |
| [`SecretField`](/docs/forms/secret-field) | Built on it, with stored-credential semantics: renders empty when a secret exists, and submitting empty means "keep it". | **Editing** a credential that already lives server-side. |

## Repeating

| Control | What it is | Reach for it when |
|---|---|---|
| [`FieldArray`](/docs/forms/field-array) | N rows with add and remove, stateless — the caller owns the values. | A field the user can have several of. |

<Callout type="warn">
`FieldArray`'s `rowKey` must be **stable across a commit**. If a row's key changes when its
value is first saved, React remounts the input and the user loses focus mid-typing — do not
"simplify" it to the array index.
</Callout>

## AI-assisted

These take suggestions from a model, and the library never calls one — you pass a stream. See
[AI-assisted fields](/docs/forms/ai) for the shared contract.

| Control | What it is | Reach for it when |
|---|---|---|
| [`SuggestMenu`](/docs/forms/suggest-menu) | A button beside a field that offers streamed candidates. | The user is choosing a value and needs options they did not think of. |
| [`GhostEditor`](/docs/forms/ghost-editor) | A textarea that completes inline as you type. | The user is writing prose and a continuation helps. |

---

Every one of these sets its state on the `Field`, never on the control — see
[Building a form](/docs/forms/building-a-form), then [Validation](/docs/forms/validation) for
how errors are shown.
