## Usage

```tsx
import { ShellBar, ShellBarStart, ShellBarCenter, ShellBarEnd } from "@kanzo-tech/ui";
```

```tsx
<ShellBar position="top">
  <ShellBarStart>{/* breadcrumbs, title, path */}</ShellBarStart>
  <ShellBarCenter>{/* a mode indicator */}</ShellBarCenter>
  <ShellBarEnd>{/* controls */}</ShellBarEnd>
</ShellBar>
```

## Why there is only one

`Toolbar`, `StatusBar` and `TopBarUtility` were three implementations of the same pattern: a
thin strip with start / center / end clusters. They existed separately only because each
specific shell brought its own — and `WorkspaceLayout` did not even use `Toolbar`, it copied
its recipe by hand into its panel header.

| Was | Now |
|---|---|
| `Toolbar` | `<ShellBar position="top" />` |
| `StatusBar` | `<ShellBar position="bottom" size="sm" />` |
| `TopBarUtility` | `<ShellBar position="top" size="lg" />` |

## Variants

`position` decides which edge carries the divider — a bar is a boundary, and the border says
which side of it the content is on.

`size` is the strip's scale: `sm` is status-bar height (the thinnest that still fits a 16px
icon), `md` is toolbar height and the default, `lg` is a taller utility strip for a bar
carrying text rather than controls.

## Accessibility

`ShellBar` renders a plain `div` and declares **no role**. Both omissions are deliberate.

<Callout type="warn">
It is **not** a `role="toolbar"`. That role promises assistive tech a single tab stop navigated
with arrow keys, and a bar holding arbitrary children — a back button, breadcrumbs, free text,
a menu — cannot provide roving focus. `Toolbar` and `StatusBar` both used to claim the role
without implementing it, which is worse than claiming nothing.
</Callout>

For a real toolbar of uniform controls, compose a `ToggleGroup` inside. Roving focus, arrow-key
navigation and `data-state` then come from Ark:

```tsx
<ShellBar aria-label="Status" position="bottom" role="contentinfo" size="sm">
  <ShellBarStart>Ready</ShellBarStart>
  <ShellBarEnd>
    <ToggleGroup aria-label="Panels" multiple onValueChange={onToggle} value={active}>
      <ToggleGroupItem aria-label="Files" value="files">
        <FilesIcon />
      </ToggleGroupItem>
    </ToggleGroup>
  </ShellBarEnd>
</ShellBar>
```

<Callout type="warn">
If you wrap those items in tooltips, **`ToggleGroupItem` must be the outer element** and the
tooltip trigger its `asChild`, never the reverse. In an `asChild` chain the outer component's
props win, and zag finds a group's items by querying
`[data-scope=toggle-group][data-part=item]`. Wrapping the item in `<TooltipTrigger asChild>`
overwrites both attributes with the tooltip's, so zag collects zero items and roving focus dies
silently. `shell.test.tsx` guards this.
</Callout>

It is not a landmark either. A bottom bar is often `role="contentinfo"`, a toolbar strip is
not, and a shell may have several bars — declaring a landmark here would mint duplicates. Pass
`role` and `aria-label` at the call site when the bar genuinely is one.
