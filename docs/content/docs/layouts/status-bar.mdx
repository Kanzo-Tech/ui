## Usage

```tsx
import { StatusBar, StatusBarStart, StatusBarCenter, StatusBarEnd } from "@kanzo-tech/ui";
```

```tsx
<StatusBar activePanel={active} onPanelToggle={setActive} panels={panels}>
  <StatusBarStart>{/* path, counts, hints */}</StatusBarStart>
  <StatusBarCenter>{/* cursor position, mode */}</StatusBarCenter>
  <StatusBarEnd>{/* encoding, language */}</StatusBarEnd>
</StatusBar>
```

StatusBar mirrors [`Toolbar`](/docs/composites/toolbar) — same compact IDE aesthetic, same card
surface, same small type — but sits at the *bottom* of a view and is bordered above, so the two
frame the canvas between them. It renders a `<footer>` landmark.

`panels` stays a prop while the regions are children, and the split is deliberate: the toggles
are data plus behaviour that the bar renders as a uniform group (each one a tooltipped,
`aria-pressed` button), not a layout region you fill. They always render after `StatusBarEnd`,
at the far end of the bar.

## Anatomy

```text
StatusBar
├── StatusBarStart    (takes the free space and truncates)
├── StatusBarCenter
├── StatusBarEnd
└── (panel toggles, rendered from `panels`)
```

Regions are named `Start`/`End`, not `Left`/`Right`: they follow the writing direction, so the
bar mirrors in RTL without a second layout.

## API Reference

### StatusBar

Renders a `<footer>`; takes its props.

| Prop | Type | Default |
| --- | --- | --- |
| `panels` | `StatusBarPanelButton[]` | `[]` |
| `activePanel` | `string \| null` | — |
| `onPanelToggle` | `(id: string) => void` | — |
| `aria-label` | `string` | `"Status bar"` |

### StatusBarPanelButton

| Prop | Type | Default |
| --- | --- | --- |
| `id` | `string` | — |
| `icon` | `ReactNode` | — |
| `label` | `string` | — |

`icon` is a pre-rendered node, so the library stays icon-library agnostic.

### StatusBarStart / StatusBarCenter / StatusBarEnd

Each renders a `div` and takes its props; none carries options of its own.
