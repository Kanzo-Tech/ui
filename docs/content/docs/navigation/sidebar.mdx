The sidebar is not one component — it is a provider, twenty-three parts, and four composites
built on top. This page is both the guide (how the pieces fit, which one to reach for) and the
reference for the base parts; the composites have their own pages.

## What you almost always want

Most applications need four things, in this order:

```tsx
<SidebarProvider>
  <Sidebar>
    <SidebarHeader>
      <InstanceSwitcher {/* … */} />   {/* who/what am I looking at */}
    </SidebarHeader>

    <SidebarContent>
      <SidebarNav items={navItems} />   {/* the navigation itself */}
    </SidebarContent>

    <SidebarFooter>
      <SidebarUser {/* … */} />         {/* who am I */}
    </SidebarFooter>
  </Sidebar>

  <SidebarInset>
    <ShellMain>{children}</ShellMain>   {/* the page — ShellMain owns the <main> */}
  </SidebarInset>
</SidebarProvider>
```

That is a complete, working sidebar. Everything below is detail you can reach for later.

<Callout type="info">
**`SidebarInset` carries no landmark.** It is the neutral offset column that holds the content
beside the rail — a `<div>`, and deliberately so. Put a [`ShellMain`](/docs/layout/shell) inside
it: the library allows **exactly one `<main>` per page** and `ShellMain` is what owns it, so
nested containers below use `<section>`. (shadcn makes its inset the `<main>` because it has no
separate region layer; we do.)
</Callout>

`SidebarProvider` owns the open state, persists it to a `sidebar_state` cookie, and binds
<kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>B</kbd> to toggle. Everything below reads that state through
`useSidebar`, which throws outside the provider. Below the `md` breakpoint the sidebar becomes a
Sheet drawer instead of a rail, which is why the navigating composites close it on click.

## The three layers

| Layer | What it is | When you touch it |
|---|---|---|
| **`SidebarProvider`** | Owns open/collapsed state, the `⌘B` shortcut and the mobile swap to a `Sheet`. Read it with `useSidebar()`. | Always — wrap once, near the root. |
| **The parts** (`Sidebar`, `SidebarHeader`, `SidebarMenu`, `SidebarMenuButton`…) | The primitive vocabulary, vendored from Shark. Twenty-three of them, documented below. | When you are building a navigation shape the composites do not cover. |
| **The composites** (`SidebarNav`, `SidebarUser`, `SidebarIdentity`, `InstanceSwitcher`) | Our pre-assembled arrangements of those parts. | Most of the time. Start here. |

The relationship is the same one the [forms guide](/docs/forms/controls) describes: the parts
are the primitive, the composites are the convenience. **Default to the composites.**

## The navigation component

There is one: [`SidebarNav`](/docs/navigation/sidebar-nav) — the **Menu**. A labelled list where
any entry may expand into sub-items. A settings-style column of several titled blocks is several
of these, one per heading, which is what the app shell does for its Platform / Support split;
there is no second composite and no `sections` prop.

It is **domain-free and router-free**: it never imports `next/link` and never reads the current
URL. Your product injects its router through the `linkComponent` seam, and tells the nav what is
active either per item (`isActive`) or once (`activePath`, prefix-matched) — the
[two models](/docs/navigation/sidebar-nav#which-row-is-active) are documented on its own page.

## Which identity component?

| Component | Where it goes | What it shows |
|---|---|---|
| [`SidebarUser`](/docs/navigation/sidebar-user) | `SidebarFooter` | The signed-in person: avatar, name, email, and a dropdown |
| [`InstanceSwitcher`](/docs/navigation/instance-switcher) | `SidebarHeader` | The thing being worked on — workspace, tenant, project — with a switcher |
| `SidebarIdentity` | inside either | The shared "icon + name + subtitle" block both are built from — documented on the [User footer](/docs/navigation/sidebar-user#the-identity-block) page |

<Callout type="warn">
`SidebarUser` has no logout prop, deliberately. Log out is an ordinary entry in `menuItems` with
`variant: "destructive"`, and your product owns the confirmation dialog and its wording — an
auth flow does not belong in a library whose admission rule excludes auth.
</Callout>

## Collapsing

`SidebarProvider` owns the state; `SidebarTrigger` toggles it and `⌘B` is bound for you. On
narrow viewports the whole sidebar becomes a `Sheet` instead of collapsing in place — that swap
is automatic and is why the provider must wrap both the sidebar and the content.

Read the state anywhere below the provider:

```tsx
const { open, isMobile, toggleSidebar } = useSidebar();
```

<Callout type="warn">
`useSidebar()` is a hook, so any component calling it is a client component. Calling it from a
server component is the single most common mistake with this API.
</Callout>

## API Reference

### SidebarProvider

| Prop | Type | Default |
| --- | --- | --- |
| `defaultOpen` | `boolean` | `true` |
| `open` | `boolean` | — |
| `onOpenChange` | `(open: boolean) => void` | — |

Extends `React.ComponentProps<"div">`.

### Sidebar

| Prop | Type | Default |
| --- | --- | --- |
| `collapsible` | `"offcanvas" \| "icon" \| "none"` | `"offcanvas"` |
| `placement` | `"left" \| "right"` | `"left"` |
| `variant` | `"sidebar" \| "floating" \| "inset"` | `"sidebar"` |
| `className` | `string` | — |

`collapsible="none"` renders a plain static `<aside>` in normal flow — the right choice when
the sidebar is embedded in a panel rather than pinned to the viewport.

### SidebarMenuButton

| Prop | Type | Default |
| --- | --- | --- |
| `isActive` | `boolean` | `false` |
| `tooltip` | `string \| TooltipContentProps` | — |
| `size` | `"xs" \| "sm" \| "md" \| "lg" \| …` | `"md"` |
| `variant` | Button variant | `"ghost"` |

The tooltip only shows while the sidebar is collapsed and not on mobile, so labelled buttons
never get a redundant one.

### SidebarContent

| Prop | Type | Default |
| --- | --- | --- |
| `scrollFade` | `boolean` | `false` |

### SidebarMenuAction

| Prop | Type | Default |
| --- | --- | --- |
| `showOnHover` | `boolean` | `false` |

### SidebarMenuSkeleton

| Prop | Type | Default |
| --- | --- | --- |
| `showIcon` | `boolean` | `false` |

### SidebarMenuSubButton

| Prop | Type | Default |
| --- | --- | --- |
| `isActive` | `boolean` | `false` |
| `size` | Button size | `"md"` |

### useSidebar

Returns `{ state, open, setOpen, isMobile, openMobile, setOpenMobile, toggleSidebar }`.
