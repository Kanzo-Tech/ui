`@kanzo-tech/testing` is how a host tests a page built with the library, in Playwright, and how the
library tests itself. This page is why it is shaped the way it is.

## A harness per component, in Angular CDK's shape

**Each component a host drives in a test has a harness: a class that knows how to find it and how
to operate it, and nothing about the page around it.** The reference is Angular CDK's Component
Harnesses. The library that owns a component ships the code that drives it, one harness per
component, written against an environment rather than a test runner. The same harness then runs in
a unit test and in an end-to-end one.

```ts
import { playwright, GraphCanvasHarness, ChartHarness, FilterBarHarness } from "@kanzo-tech/testing";

const env = await playwright(page);                              // before the page loads
await page.goto("/archive");
const lon = await env.getHarness(ChartHarness.with({ title: "Count by Airport.lon" }));
await lon.brush({ x: [-125, -100] });                            // data, not pixels
const graph = await env.getHarness(GraphCanvasHarness);
await graph.frame();                                             // waits for the drawn frame to change
await expect.poll(async () => (await env.getHarness(FilterBarHarness)).readout()).toBe("611 of 3,218 Airport");
```

| Harness | Operates |
| --- | --- |
| `GraphCanvasHarness` | `ready`, `run`, `pause`, `lasso(points, { in: "data", with })`, `marquee`, `frame`, `screenOf`, `counts` |
| `ChartHarness` | `brush({ x, y })`, `pick({ x })` by value, `busy`, `settled` |
| `TimelineHarness` | `brush([from, to])`, `range`, `play`, `pause` |
| `DashboardHarness` | `tile(title)`, a `TileHarness`; `settled` |
| `FilterBarHarness` | `chips`, `remove(field)`, `open(field)`, `readout` |
| `RelationPickerHarness` | `root`, `pick(type)`, `add(hop)` by sentence, step or label, `path`, `remove(sentence)` |
| `AnswerHarness` | `ask(question)`, `answer`, `addToDashboard`, `openOnDashboard`, `filterTo` |
| `FindingsBadgeHarness` | `tally`, `groups`, `item(message)`: a `FindingsItemHarness` with `severity`, `count`, `where`, `act` and, for a group, `sample` |
| `DockHarness` | `open(panel)`, `close`, `current` |

[Testing](/docs/testing) is the reference.

Two environments: `playwright(page)` for a host's end-to-end suite and the docs' showcases, and
`dom(container)` over Testing Library for the library's own tests. So the library's unit tests
exercise the harness a host relies on.

**It replaced each host writing its own**: Keasy's demos found a chart by an `<article>` holding a
heading, clicked at `width * 0.35` of it, brushed from `0.231` to `0.292` of a histogram's width to
mean 125°W to 100°W, and waited fixed milliseconds for what a click did. Every one of those knew the
library's markup and broke when it changed.

**The environment is made before the page loads**, so `playwright(page)` is awaited: it registers
each [model double](#one-model-double) with `addInitScript`, before the page's own scripts resolve a
model. A page already loaded resolved its models without it.

**What would reverse it:** a host whose tests drive the components through their public props
rather than the screen, such as component tests that mount a `Dashboard` with a spec. Then the
harnesses are a convenience for end-to-end alone, and the `dom` environment goes.

*Held by* `packages/ui/src/harnesses.test.tsx`, "reads the readout once it has counted, and a clause
as a chip it removes by its field", and `packages/testing/e2e/workspace.e2e.test.ts`, "picks a bar by
its value, and removing the beast filter from the bar retracts it" — the same `FilterBarHarness`, once
in jsdom and once in Chromium.

## ARIA first, `data-*` last

**A harness finds and waits on what assistive technology reads, in Testing Library's order: role,
accessible name, text, and a `data-*` attribute only where nothing accessible says it.** What the
library already exposes stays the contract: `GraphStatus` and `GraphCounts` are `aria-busy` with live
text, the layout's transport button is `aria-pressed`, `FilterBar` is the region *Filters*, a dock
switcher is a `radiogroup` whose open panel is checked, and a tile is an `article` holding its title.
What is added is accessible first. `ChartRoot` is a `figure` named by its title and `aria-busy` until
it has drawn and while its query runs; `GraphCanvas` is `aria-busy` until its first drawn frame; a
`Dashboard` is `aria-busy` while it reads its fields, and `FilterBar`'s readout is a `status`,
`aria-busy` while it counts. An answer card is `aria-busy` while the model writes and the engine
reads, then holds its tile — an `article` — or a `Problem`; a harness waits for one of the two,
because the card reads its fields over a skeleton after it stops being busy. A timeline's range will
be a group whose `aria-valuetext` reads *1950 – 1960*.

One attribute is added with no accessible equivalent: `GraphCanvas`'s `data-frame`, a count of frames
drawn, which is how a harness waits for the camera to have moved and how it finds the canvas. Two
harnesses find their host by an existing `data-slot`, because nothing accessible tells it apart: a
`Dashboard`, a column of cards that is not a landmark, and a findings badge, which is one popover
trigger among others. An answer card's frame is found by its `data-slot` too: the tile inside it is
an `article`, and the frame holding the tile and its actions has no role. A finding's severity is its row's `data-variant`, because the words a reader
sees, *Errors* or *2 warnings*, are the host's.

A harness never waits for a fixed time. It waits for a state, with Playwright's assertions that
retry on their own.

**What would reverse it:** a state a reader can perceive that no ARIA role or property describes,
measured in a component. Then that component gets a `data-*` of its own, named in this section.

*Held by* `packages/testing/src/environment.test.ts`, "fails a wait with what it waited for, never
after a fixed time with nothing to say"; `packages/ui/src/harnesses.test.tsx`, "settles once the
fields are read and no tile is loading, then finds a tile by its title"; and
`packages/graph/src/parts/graph-canvas-harness.test.tsx`, "ready() rejects a canvas that finished
loading without drawing a frame, as one with no WebGL does".

## A canvas says where it draws on its element

**What a WebGL canvas knows and its DOM does not — where a vertex is on screen — `GraphCanvas` says on
its element, in every page: `screenOf(vertex)` and `screenAt({ x, y })`, in pixels from its top-left
corner, from cosmos.gl's own `spaceToScreenPosition`.** Nothing in the library looks for a test, and
there is no global a test defines. Decided 16 October 2026.

The reference is Observable Plot, which puts `scale(channel)` on the output it returns: which pixel is
125°W is a property of what Plot drew, documented on its return value, and `ChartHarness` reads it off
the DOM element. A graph canvas is the same case with a live answer — the camera moves — so the
element carries the function rather than a snapshot. A harness runs it in the page, as it runs
everything else.

It replaced `window.__KANZO_TESTING__`, a global the harness environment defined before the page
loaded and `GraphCanvas` registered with when it found it, on the model of React DevTools'
`__REACT_DEVTOOLS_GLOBAL_HOOK__`. That was a branch in the code that ships, reading a global
production "never defines" — the shape `/local` had already given up for models
([below](#a-model-is-resolved-through-one-registry)) — and it made the environment's timing a
condition of the canvas's: a page loaded before the hook was installed had canvases a harness could
not read. An element's two functions have no such condition and no type to share: `@kanzo-tech/testing`
declares them by shape, and imports nothing of the components'.

**What would reverse it:** a canvas whose content is in the accessibility tree, such as a graph
rendered with an accessible table of its vertices beside the canvas. Then a harness reads that, and
the element's two functions go. Or a second consumer of the two functions that is not a test — a
tour pointing at a vertex — which makes them API in their own right, named on the reference page.

*Held by* `packages/graph/src/parts/graph-canvas-harness.test.tsx`, "says where it draws on its
element, in every page, and takes it off when it unmounts"; `packages/ui/src/harnesses.test.tsx`,
"reads where a value falls from the scale Plot puts on its own output, with no chart registered
anywhere"; `packages/testing/src/environment.test.ts`, "defines no global of its own: a model script
is a provider in the registry, asked nothing yet"; and, in Chromium over the workspace showcase in
CI's harnesses job, `packages/testing/e2e/workspace.e2e.test.ts`, "draws the archive, and a lasso
around a vertex gives the canvas a clause" and "brushes a range in data, through the chart's own
scale".

*Held by*, for the parts other changes delivered, `packages/ui/src/harnesses.test.tsx`, "opens
a panel by its label, and collapses the dock when the open one is pressed again", over
`ShellDockSwitcher`; `packages/ai/src/data/answer-harness.test.tsx`, "waits for the card to answer,
reads its tile, and filters the page to it", "adds the answer to the dashboard, through the host's
pending write, and waits for the card to say it is there", "rejects an add the host refused with the
words of the card's Problem" and "rejects an answer that failed with the words of its Problem", over
`AnswerCard`; and `packages/testing/e2e/workspace.e2e.test.ts`, "asks a question the
recording knows, reads the answer's chart, and filters the page to it".

*Held by*, for `TimelineHarness` over `ChartTimeline`, `packages/graph/src/parts/timeline.test.tsx`,
"is driven by TimelineHarness: the window the group reads, and play and pause through the one
button" — in jsdom, with the brush moved as a drag would move it, because jsdom has no layout for a
pointer to cross. Its `brush` is `ChartHarness`'s, which the end-to-end suite holds in Chromium;
a timeline on the workspace showcase is what would hold the timeline's own there.

## The names are CDK's

**Where Angular CDK's harness API has an operation, ours has its name; where it has none, or its
namesake does something else, ours keeps its own and says why here.** This page names CDK as the
reference, and the package first used other words for the same things with no reason written down —
which is a divergence nobody decided. Decided 13 October 2026.

| Ours | CDK's | |
| --- | --- | --- |
| `env.getHarness(query)`, `env.getAllHarnesses(query)`, `env.rootElement` | the same | were `harness`, `harnesses`, `root` |
| `locatorFor(query, what?)` | `locatorFor(query)` | was `locate(query)` and `one(by, what)`, now one: CDK's locator takes a harness query or an element's query alike and returns the function that finds it. The function takes another element to search instead of the host, and `what` is the words a wait that runs out fails with. `locatorForOptional` and `locatorForAll` are not built: `getAllHarnesses` and a `TestElement`'s `find` answer what they would, and no harness has asked |
| `ComponentHarnessConstructor` | the same | was `HarnessType` |
| `TestElement` | the same | was `Handle` |
| `getAttribute(name)` | the same | was `attribute` |
| `getDimensions()`, an `ElementDimensions` of `top`, `left`, `width`, `height` | the same | was `rect()`, a `Rect` of `x`, `y`, `width`, `height` |
| `sendKeys(key)` | the same | was `press`. One key, by its `KeyboardEvent.key`, as every caller sends |
| `text`, `click` | the same | already CDK's |
| `static by` | `hostSelector` | kept: a `By` is Testing Library's query — role, name, text — not a selector |
| `HarnessQuery` | `HarnessQuery` | kept; CDK's is a constructor or a predicate, ours a constructor and its `By` |
| `fill(value)` | — | kept: CDK's `setInputValue` sets the property and dispatches nothing; ours types as a person does, as Playwright's `fill` |
| `until`, `reveal`, `drag`, `evaluate`, `ariaBusy`, `find` | — | kept: CDK waits on Angular's zone, and has no drag or scroll; ours waits on a state |

And one duplicate went: testing's `Severity` was `@kanzo-tech/ui`'s `FindingSeverity` under another
name. `FindingsItemHarness.severity()` answers the same union, unnamed — the package imports nothing
of the components', so it cannot import the name, and naming it a second time is the duplicate — and
a test in `ui` holds the two equal.

**What would reverse it:** a CDK name that misleads a reader of our harnesses into expecting CDK's
behaviour — then that row is kept as ours, with the reason, as `fill` is.

*Held by* `packages/testing/src/environment.test.ts`, "locates a part's harness or an element inside
the host, and says what it waited for when neither comes"; `packages/ui/src/harnesses.test.tsx`,
"reads a severity as FindingSeverity, the one name it has".

## One model double

**`@kanzo-tech/llm/testing` ships one scripted model — the AI SDK's `MockLanguageModelV4` answering
from a script of turns — and an end-to-end test registers the same script as a model id's provider.**
A unit test passes `scriptedModel(script)` where a model goes; an end-to-end test registers a script
for a model id through `playwright(page, { models })`, before the page loads, and the product's code
never knows ([below](#a-model-is-resolved-through-one-registry)). Decided 13 October 2026.

There were five: `@kanzo-tech/ai`'s test double, the docs' mock model *with the same shape as* it,
keasy's hand-written model injected on `window.__keasyModelDouble` — a test global of its own —
keasy's branch in its model module that serves it with a guard test that it never ships, and keasy's
fixture over `MockLanguageModelV4`. A model the page cannot serve is
`llm/unavailable`, `localModel`'s own answer, and no double is needed to say it.

**The script is data** — `ModelScript`, declared in `@kanzo-tech/testing` — because a function does
not cross into the page. Its shape is keasy's double's, the one with the most scenarios behind it:
each call answered by the first turn whose `when` its prompt contains, `once` to answer one call and
give way, and a reply that is text with its thinking, an object, a tool call, a failure — a stream's
after its first words — or a call that hangs until it is stopped; a `pace` for a recording, and a
load that fails. In a unit test the turns may be a function of the call instead, for an answer that
is computed, as the docs' recordings recognise a question they were not given word for word; that
never crosses into a page.

**The answering is one function, `scripted(script)`, in `@kanzo-tech/testing`, and it closes over
nothing but `promptOf`.** A page cannot import the mock: the page's bundle is the one that ships, and
`ai/test` is not in it. What crosses into a page is source text — Playwright's `addInitScript` — so
the answering is written to be sent as text: `promptOf`, `scripted` and the registration, declared,
then called with the scripts as JSON. In this process `scriptedModel` is the SDK's mock over the same
`scripted`, for the calls the SDK records on it. It lives beside the script rather than in `llm`
because `testing` imports nothing of `llm`'s and `llm/testing` already depends on `testing`.

**What would reverse it:** a test that needs a model whose behaviour a script cannot state — a tool
call's input streamed as it is written, say. Then the script grows that, and it is still the one
double. And `scripted` written in a module the page's bundle can import without shipping it — a
bundler's test build that is the build that ships — would let the page take the mock itself.

*Held by* `packages/llm/src/testing.test.ts`, "answers each call with the first turn whose words its
prompt holds, and a once turn only once"; `packages/testing/src/environment.test.ts`, "defines no
global of its own: a model script is a provider in the registry, asked nothing yet" and "registers a
provider per scripted id in the model registry, from a script that closes over nothing".

## A model is resolved through one registry

**`localModel(id)` has one path: it asks one provider registry for `id`, and production code names
no test.** The registry is on `globalThis` under `Symbol.for("@kanzo-tech/llm/local")`:

```ts
interface LocalModelRegistry {
  languageModels: Map<string, LocalEngine>; // by id: { model, load }, registered first
  fallbackProvider?: LocalProvider;         // the host's: setLocalProvider(localProvider({ baseURL, worker }))
}
```

A model registered for `id` answers first; else the host's provider; else WebLLM's own prebuilt
list. Without an id, `localModel()` asks the first registered, else the first the provider lists. A
host sets its provider once, at its composition root, with where its models are served from:
`localProvider({ baseURL: "/models" })` serves exactly what `/models/app-config.json` lists, and that
file is **WebLLM's own `AppConfig`**, untranslated — the consumer is WebLLM, so its config is the
format. The host's code names no model and no library version; whatever downloads the models writes
the file beside them. A test's environment registers a provider per scripted id in `languageModels`,
before the page's own scripts run, through `addInitScript`, and records each prompt on the model it
registers, which `env.prompts(id)` reads.

It replaced two branches and a second mechanism. `/local` read `__KANZO_TESTING__` itself and, when a
script was there for its id, imported the double lazily — a test branch in the code that ships, and
a chunk of `ai/test` in every production bundle that reached `/local`. And where a model's files
came from was a setting of its own, `from: { weights, library }`, passed beside the engine choice on
every call, so keasy kept a `ModelProvider` of its own to carry a URL and a second double-detecting
branch around it. A provider configured with where it loads from is both at once.

The references:

- **The AI SDK's provider registry** — `createProviderRegistry` and `customProvider({ languageModels,
  fallbackProvider })`, a model resolved by id from registered providers, and `createOpenAI({ baseURL
  })`, a provider configured with where it is served. `languageModels` and `fallbackProvider` are its
  names. `registry.languageModel(id)` names one model when it must; `localModel()` asks the first
  served for the same reason.
- **OpenTelemetry's global provider API** — `trace.setGlobalTracerProvider(provider)`: the library
  reads one global, a default until something registers, under a `Symbol.for` key so that every
  copy of the code finds the same one. `setLocalProvider` is its shape.
- **WebLLM's `AppConfig`** — `{ model_list: [{ model, model_id, model_lib, … }] }`, the type
  `@mlc-ai/web-llm` declares and its prebuilt list is; served as a file it is what `localProvider`
  reads. **Transformers.js's `env.localModelPath`** is the same move in the other in-browser runtime:
  one base on the host's origin that every model is read under.

Not the AI SDK's own global, `globalThis.AI_SDK_DEFAULT_PROVIDER`: it resolves every *string* model
id a host passes anywhere, a gateway's among them, and a page that ran a model in it and called a
server with another would have one global answering for both.

**The threat, stated plainly.** A script that runs before the app can register a provider, and the
app will answer with it. It could equally replace `Worker`, `WebAssembly`, `fetch` or `navigator.gpu`
before the app reads them, and WebLLM would run on whatever it found. No design can exclude a script
that runs first and still let a test drive the build that ships — that is what testing the build that
ships means — so the registry adds no capability such a script lacked. What it removes is the test
branch: the code that ships no longer looks for a test, so it cannot be fooled into thinking it is
in one. A page's Content Security Policy is what decides which scripts run first, as it always was.

**What would reverse it:** a second engine in the page whose models are not WebLLM's — a
Transformers.js model beside a WebLLM one. Then `app-config.json` is no longer the one listing, and
the provider takes a listing per engine, or the registry a provider per engine, as the AI SDK's takes
a provider per prefix. And a page that must refuse any provider it did not set itself — a host that
cannot trust its first scripts — would need the registry closed after boot, which also closes it to
its tests; nothing here has asked.

*Held by* `packages/llm/src/local.test.ts`, "answers from the script registered for its id, records
the prompt, and never reaches WebLLM", "asks the first scripted id when no id is asked, before the
host's provider lists anything", "answers with WebLLM when nothing registered the id", "serves every
model its app-config.json lists, in order, the first when no id is asked, with WebLLM's config handed
on as written" and "is unserved when the listing is missing, lists nothing, or does not list the id
asked".

## A test reads from one real engine, and a model's test replays a recording

*Status: to be built.* The tree has the macros and the doubles this section deletes; ui #220 removes
the first.

**Every test that needs a database runs on DuckDB-WASM in Node. There is no native DuckDB and no
double that imitates one.** The belief that "this build of DuckDB-WASM cannot open a Parquet file in
Node" was wrong, and the macros in `packages/graph`'s test fixture that stood in for
`parquet_metadata` were written on it. The cause was the test environment: vitest's `jsdom`
installs its own `XMLHttpRequest` on `globalThis`. DuckDB-WASM loads its `parquet` extension on the
first statement that reads one, and if an `XMLHttpRequest` exists it tries a synchronous request for
the extension; jsdom refuses a synchronous request that sets `responseType` with an
`InvalidAccessError`, the exception escapes through the engine's frames, and the instance is broken
for the rest of the file. With no `XMLHttpRequest` the extension is already present, nothing is
fetched, and Parquet with ZSTD opens offline, from a registered buffer or a file path. Measured on
`1.33.1-dev57.0` (the engine's pin) and on fossil's `1.32.0`, in the `mvp` and `eh` bundles.

The rule: **a file that opens a Parquet file declares `// @vitest-environment node`, or removes the
`XMLHttpRequest` global before its first Parquet statement.** The tests of `graph` that need
`jsdom` for a canvas keep it in their own files and do not touch an engine. The page's code stays as
it is: a browser has no synchronous-XHR trap, and the boot loads its extensions from the tarball
([the engine](/docs/design/engine#the-engines-own-surface-files-and-boot)).

**Fixtures are the datasets, written by fossil, and nothing is hand-footed.** Three are canonical:
the Nobel laureates, OpenFlights (the airports) and LDBC SNB. Each is `mapping.fossil`, `shapes.shex`
and a `fetch.sh` in keasy's `infra/dev/examples/`, written to a graph by fossil's executor; the docs'
archive and Ask's evaluation set already run on the same programs. Cordis stays a demo and is not a
fixture. A test that needs a chunk with a property of its own (a footer key, a row-group statistic)
writes it in-process with `COPY … (FORMAT parquet, COMPRESSION zstd, KV_METADATA {…})` on the same
engine, and `parquet_kv_metadata` reads the key back, so the footer a reader parses is DuckDB's own.

**The one exception is the integration test of fossil's executor**, which installs a synchronous
`XMLHttpRequest` and so downloads `httpfs` and `parquet` from `extensions.duckdb.org`: it needs the
network at test time, and says so. Not run here: ui's `attachGraph` and SQL against these files,
and `jsdom` 25 (only 29 was tried).

**What would reverse it:** a DuckDB-WASM release that no longer loads an extension through
`XMLHttpRequest`, which removes the node-environment rule and nothing else; or a fixture too large to
write in a test run, which becomes a written graph fetched once in CI.

**A model's test replays a recording; the model's quality is measured live, once, by hand.** A
recording (a cassette) is a `ModelScript` that a recorder wrote instead of a person: one entry per
call, **keyed by the model's digest, its parameters and the hash of the prompt**. CI replays it
through the registry the double already uses, so the code under test cannot tell the two apart.
**A call whose key is not in the cassette fails the test, loudly, naming the prompt hash it saw and
the nearest it holds**: a changed prompt never reaches a model silently and never gets a stale
answer. A cassette is re-recorded on a machine with a GPU, with a **seed**, and the seed is stored in
it. The evaluation set below is not replayed: it measures the model, so it runs live and seeded, and
its results line carries the seed.

**A mapping is compared by what it does.** A test of a `Mapping` (rudof's, `describe`'s, the
attacher's) compares canonical forms or asks that the same data yields the same triples, and never
compares the bytes of a serialisation: two writers print one mapping in many orders. This is the rule
a mapping's reader gets for its own tests.

**What would reverse the replay:** a model that cannot be seeded, which leaves a recording a
snapshot of one draw and no more; the cassette then holds the evidence of a run and nothing is
asserted from its content. Nothing is held by a test yet: none of this exists.

## Ask's evaluation set lives beside Ask

**The evaluation set that scores Ask is `packages/ai/eval`, beside the Task it measures and outside
the package's published `files`.** It measures `@kanzo-tech/ai/data`'s Ask and nothing of a
product's: a case is a page's relation and filter, the questions asked in turn, and the rows the
last answer must and must not have been read from — execution accuracy, as
[Asking data](/docs/design/ai#ask-is-evaluated-as-a-dataset-a-solver-and-a-scorer) defines the set. It came from keasy's `e2e/eval` on 14 October
2026 and runs as it ran there; what changed is what it is driven through. In keasy it ran through
keasy's pages, polled on a two-second loop and reached the card by `data-slot`; here it drives the
library's own Ask through the harnesses a host uses, and waits on states. Decided 13 October 2026.

| **Results** | one line per case in `packages/ai/eval/results/<model>/ask.jsonl`, `.gitignore`d; a case that fails is a result, and the run fails only when it cannot ask |
| **When** | by hand, `pnpm --filter @kanzo-tech/ai eval` with the docs running, before a change to Ask or to the model; never in `pnpm verify` and never on CI, which has no GPU. `EVAL_DOUBLE=1` is the smoke run: five cases on the one model double, answering with the specs a right answer is, to show the runner, the page and the scoring work on a machine with no GPU. It scores nothing |

The set is data apart from its runner, so the second runner [Tasks](/docs/design/tasks#everything-in-the-browser-the-model-too)
names — the same weights on native llama.cpp in CI — reads the same cases when it is built.

**What was not moved.** keasy's `cases.ts` also held four cases for its assistant — the files a person
picks and what the data is about, per dev example. They are the assistant's, not Ask's, and no runner
read them; they stay keasy's, with its assistant.

**No baseline yet.** The machine that moved the set has no GPU: WebLLM downloads the weights and then
fails to start its engine, and every case is recorded as *the model cannot run in this browser*. The
only number there is predates Ask as a Task — keasy's reference pass of 12 October 2026, 2 of 10 on
Qwen3 4B — so the first run on a GPU is the baseline the join and answer model is measured against.

**The docs' fossil is `0.3.0-alpha.31`, the version keasy's examples were last run on.** The SNB
program names a column the datagen wrote twice, `KnowsRow."Person.id_1"`, and `alpha.28` does not
parse a quoted name.

**What would reverse it:** a second product's evaluation set over Ask with cases of its own — then
the runner is the shared part, and each product keeps its cases.
