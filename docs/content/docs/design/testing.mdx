title: Testing a page built with Kanzo UI
description: Why @kanzo-tech/testing ships a harness per component in Angular CDK's shape, reads ARIA before anything else, and reaches a canvas's coordinates only through a hook a test installs — and what would reverse each rule.

`@kanzo-tech/testing` is how a host tests a page built with the library, in Playwright, and how the
library tests itself. This page is why it is shaped the way it is.

## A harness per component, in Angular CDK's shape

**Each component a host drives in a test has a harness: a class that knows how to find it and how
to operate it, and nothing about the page around it.** The reference is Angular CDK's Component
Harnesses. The library that owns a component ships the code that drives it, one harness per
component, written against an environment rather than a test runner. The same harness then runs in
a unit test and in an end-to-end one.

```ts
import { playwright, GraphCanvasHarness, ChartHarness, FilterBarHarness } from "@kanzo-tech/testing";

const env = await playwright(page);                              // installs the test hook, then the page loads
await page.goto("/archive");
const lon = await env.harness(ChartHarness.with({ title: "Count by Airport.lon" }));
await lon.brush({ x: [-125, -100] });                            // data, not pixels
const graph = await env.harness(GraphCanvasHarness);
await graph.frame();                                             // waits for the drawn frame to change
await expect.poll(async () => (await env.harness(FilterBarHarness)).readout()).toBe("611 of 3,218 Airport");
```

| Harness | Operates |
| --- | --- |
| `GraphCanvasHarness` | `ready`, `run`, `pause`, `lasso(points, { in: "data", with })`, `marquee`, `frame`, `screenOf`, `counts` |
| `ChartHarness` | `brush({ x, y })`, `pick({ x })` by value, `busy`, `settled` |
| `TimelineHarness` | `brush([from, to])`, `range`, `play`, `pause` |
| `DashboardHarness` | `tile(title)`, a `TileHarness`; `settled` |
| `FilterBarHarness` | `chips`, `remove(field)`, `open(field)`, `readout` |
| `RelationPickerHarness` | `root`, `pick(type)`, `add(hop)` by sentence, step or label, `path`, `remove(sentence)` |
| `AnswerHarness` | `ask(question)`, `answer`, `addToDashboard`, `openOnDashboard`, `filterTo` |
| `FindingsBadgeHarness` | `tally`, `groups`, `item(message)`: a `FindingsItemHarness` with `severity`, `count`, `where`, `act` and, for a group, `sample` |
| `DockHarness` | `open(panel)`, `close`, `current` |

[Testing](/docs/testing) is the reference.

Two environments: `playwright(page)` for a host's end-to-end suite and the docs' showcases, and
`dom(container)` over Testing Library for the library's own tests. So the library's unit tests
exercise the harness a host relies on.

**It replaced each host writing its own**: Keasy's demos found a chart by an `<article>` holding a
heading, clicked at `width * 0.35` of it, brushed from `0.231` to `0.292` of a histogram's width to
mean 125°W to 100°W, and waited fixed milliseconds for what a click did. Every one of those knew the
library's markup and broke when it changed.

**The environment is made before the page loads**, so `playwright(page)` is awaited: it installs the
hook with `addInitScript`, and a component registers while it mounts. A page already loaded mounted
without it.

**What would reverse it:** a host whose tests drive the components through their public props
rather than the screen, such as component tests that mount a `Dashboard` with a spec. Then the
harnesses are a convenience for end-to-end alone, and the `dom` environment goes.

*Held by* `packages/ui/src/harnesses.test.tsx`, "reads the readout once it has counted, and a clause
as a chip it removes by its field", and `packages/testing/e2e/workspace.e2e.test.ts`, "picks a bar by
its value, and removing the beast filter from the bar retracts it" — the same `FilterBarHarness`, once
in jsdom and once in Chromium.

## ARIA first, `data-*` last

**A harness finds and waits on what assistive technology reads, in Testing Library's order: role,
accessible name, text, and a `data-*` attribute only where nothing accessible says it.** What the
library already exposes stays the contract: `GraphStatus` and `GraphCounts` are `aria-busy` with live
text, the layout's transport button is `aria-pressed`, `FilterBar` is the region *Filters*, a dock
switcher is a `radiogroup` whose open panel is checked, and a tile is an `article` holding its title.
What is added is accessible first. `ChartRoot` is a `figure` named by its title and `aria-busy` until
it has drawn and while its query runs; `GraphCanvas` is `aria-busy` until its first drawn frame; a
`Dashboard` is `aria-busy` while it reads its fields, and `FilterBar`'s readout is a `status`,
`aria-busy` while it counts. An answer card is `aria-busy` while the model writes and the engine
reads, then holds its tile — an `article` — or a `Problem`; a harness waits for one of the two,
because the card reads its fields over a skeleton after it stops being busy. A timeline's range will
be a group whose `aria-valuetext` reads *1950 – 1960*.

One attribute is added with no accessible equivalent: `GraphCanvas`'s `data-frame`, a count of frames
drawn, which is how a harness waits for the camera to have moved and how it finds the canvas. Two
harnesses find their host by an existing `data-slot`, because nothing accessible tells it apart: a
`Dashboard`, a column of cards that is not a landmark, and a findings badge, which is one popover
trigger among others. An answer card's frame is found by its `data-slot` too: the tile inside it is
an `article`, and the frame holding the tile and its actions has no role. A finding's severity is its row's `data-variant`, because the words a reader
sees, *Errors* or *2 warnings*, are the host's.

A harness never waits for a fixed time. It waits for a state, with Playwright's assertions that
retry on their own.

**What would reverse it:** a state a reader can perceive that no ARIA role or property describes,
measured in a component. Then that component gets a `data-*` of its own, named in this section.

*Held by* `packages/testing/src/environment.test.ts`, "fails a wait with what it waited for, never
after a fixed time with nothing to say"; `packages/ui/src/harnesses.test.tsx`, "settles once the
fields are read and no tile is loading, then finds a tile by its title"; and
`packages/graph/src/parts/graph-canvas-harness.test.tsx`, "ready() rejects a canvas that finished
loading without drawing a frame, as one with no WebGL does".

## A canvas's coordinates come through a hook only a test installs

**What a WebGL canvas or a chart's scale knows — where a vertex is on screen, which pixel is 125°W —
reaches a harness through `window.__KANZO_TESTING__`, which the harness environment defines before
the page loads and which production never has.** Each root registers itself when it finds the hook,
and does nothing otherwise:

```ts
interface KanzoTestingHook {
  graphs: Map<string, { screenOf(vertex: number): [number, number]; screenAt(point: { x: number; y: number }): [number, number] }>;
  charts: Map<string, { scale(channel: "x" | "y" | "color"): { apply(value: unknown): number; invert?(pixel: number): unknown } }>;
}
```

The reference is tldraw and Excalidraw, whose end-to-end suites reach the editor a test exposes,
and React DevTools' `__REACT_DEVTOOLS_GLOBAL_HOOK__`, a global the tool defines and the library
registers with. A chart's scale is Observable Plot's own `figure.scale(channel)`.

**What would reverse it:** a canvas whose content is in the accessibility tree, such as a graph
rendered with an accessible table of its vertices beside the canvas. Then a harness reads that, and
the graph's half of the hook goes.

The type is declared once, in `@kanzo-tech/testing`, because that package installs the hook. `ui` and
`graph` import it as a type from a devDependency, so it never reaches what they publish, and the
testing package imports nothing of theirs: no cycle, and a harness runs against whatever version of
the components a page loaded. A chart registers under its `aria-label`; a chart with no title is not
one a harness can name, and is not registered.

*Held by* `packages/graph/src/parts/graph-canvas-harness.test.tsx`, "registers with the test hook
under its id when one is installed, and lets go of it when it unmounts" and "registers nothing when no
test installed the hook"; `packages/ui/src/harnesses.test.tsx`, "registers nothing when no test
installed the hook, nor a chart with no title"; and, in Chromium over the workspace showcase in CI's
harnesses job, `packages/testing/e2e/workspace.e2e.test.ts`, "draws the archive, and a lasso
around a vertex gives the canvas a clause" and "brushes a range in data, through the chart's own
scale".

*Held by*, for the parts other changes delivered, `packages/ui/src/harnesses.test.tsx`, "opens
a panel by its label, and collapses the dock when the open one is pressed again", over
`ShellDockSwitcher`; `packages/ai/src/data/answer-harness.test.tsx`, "waits for the card to answer,
reads its tile, and filters the page to it", "adds the answer to the dashboard, through the host's
pending write, and waits for the card to say it is there", "rejects an add the host refused with the
words of the card's Problem" and "rejects an answer that failed with the words of its Problem", over
`AnswerCard`; and `packages/testing/e2e/workspace.e2e.test.ts`, "asks a question the
recording knows, reads the answer's chart, and filters the page to it".

*Not yet held*: `TimelineHarness`. `ChartTimeline` ships, and its test is still skipped as *not yet
built*; the cleanup's first PR runs it ([the release plan](/docs/design/cleanup#the-release-plan)).

## The names are CDK's

<Callout type="warn">**A direction, not built.** Decided 13 October 2026.</Callout>

**Where Angular CDK's harness API has an operation, ours has its name; where it has none, or its
namesake does something else, ours keeps its own and says why here.** The page names CDK as the
reference and then used other words for the same things, with no reason written down — which is a
divergence nobody decided.

| Ours | CDK's | |
| --- | --- | --- |
| `env.harness(query)` | `getHarness` | renamed |
| `env.harnesses(query)` | `getAllHarnesses` | renamed |
| `env.root` | `rootElement` | renamed |
| `locate(query)` and `one(by, what)` | `locatorFor(query)`, with `locatorForOptional` and `locatorForAll` | renamed, and one: CDK's locator takes a harness query or an element's query alike and returns the function that finds it |
| `HarnessType` | `ComponentHarnessConstructor` | renamed |
| `Handle` | `TestElement` | renamed |
| `attribute(name)` | `getAttribute` | renamed |
| `rect()`, a `Rect` | `getDimensions()`, an `ElementDimensions` of `top`, `left`, `width`, `height` | renamed, and CDK's shape |
| `press(key)` | `sendKeys` | renamed |
| `text`, `click` | `text`, `click` | already CDK's |
| `static by` | `hostSelector` | kept: a `By` is Testing Library's query — role, name, text — not a selector |
| `HarnessQuery` | `HarnessQuery` | kept; CDK's is a constructor or a predicate, ours a constructor and its `By` |
| `fill(value)` | — | kept: CDK's `setInputValue` sets the property and dispatches nothing; ours types as a person does, as Playwright's `fill` |
| `until`, `reveal`, `drag`, `evaluate`, `ariaBusy`, `find` | — | kept: CDK waits on Angular's zone, and has no drag or scroll; ours waits on a state |

And one duplicate goes: testing's `Severity` is ui's `FindingSeverity` under another name.

**What would reverse it:** a CDK name that misleads a reader of our harnesses into expecting CDK's
behaviour — then that row is kept as ours, with the reason, as `fill` is.

**Breaking**, in a consumer's words: in your page objects, `harness(` is `getHarness(`,
`harnesses(` is `getAllHarnesses(`, `Handle` is `TestElement`, `.attribute(` is `.getAttribute(`,
`.rect()` is `.getDimensions()` with `top` and `left` in place of `y` and `x`, `.press(` is
`.sendKeys(`, and `locate` and `one` are `locatorFor`. `Severity` is `FindingSeverity`, from
`@kanzo-tech/ui`.

## One model double

<Callout type="warn">**A direction, not built.** Decided 13 October 2026.</Callout>

**`@kanzo-tech/llm/testing` ships one scripted model — the AI SDK's `MockLanguageModelV4` answering
from a script of turns — and `localModel` answers with it in place of the real model when a test
has registered one on `__KANZO_TESTING__`.** A unit test passes the double where a model goes; an
end-to-end test registers a script for a model id through `playwright(page, { models })`, before the
page loads, as a canvas registers its coordinates ([above](#a-canvass-coordinates-come-through-a-hook-only-a-test-installs)),
and the product's code never knows. The script is data — the turns' texts and objects — because a
function does not cross into the page.

There were five: `@kanzo-tech/ai`'s test double, the docs' mock model *with the same shape as*
it, keasy's hand-written model injected on `window.__keasyModelDouble` — the hook this page already
installs, reinvented — keasy's branch in its model module that serves it with a guard test that it
never ships, and keasy's fixture over `MockLanguageModelV4`. A model the page cannot serve is
`llm/unavailable`, `localModel`'s own answer, and no double is needed to say it.

**What would reverse it:** a test that needs a model whose behaviour a script cannot state — a
latency, a stream cut half-way. Then the script grows that, and it is still the one double.

**Breaking**, in a consumer's words: register your model double with `playwright(page, { models })`
and delete the one you inject; import the unit-test double from `@kanzo-tech/llm/testing`.

## Ask's evaluation set lives beside Ask

<Callout type="warn">**A direction, not built.** Decided 13 October 2026.</Callout>

**The evaluation set that scores Ask moves from keasy's `e2e/eval` to `packages/ai/eval`, beside the
Task it measures, outside the package's published `files`.** It measures `@kanzo-tech/ai/data`'s
`ask` and nothing of keasy's: a case is a page's relation and filter, the questions asked in turn,
and the rows the last answer must and must not have been read from — execution accuracy, as
[Tasks](/docs/design/tasks#phases) defines the set. In keasy it ran through keasy's pages, polled on a
two-second loop and reached the card by `data-slot`; here it drives Ask through the harnesses a host
uses and waits on states.

| | |
| --- | --- |
| **Cases** | `packages/ai/eval/cases.ts`, data: Nobel for nearly every shape, LDBC SNB for self-joins and a large graph. Each case says the failure it tests. A tie no longer asks: with paths, a case that tested *which way should this be counted?* expects the model's path, and its chip's alternative |
| **Corpora** | written by fossil's executor in Node through `docs/scripts/write-corpus.mjs`, as the docs' archive is, from each example's program, shapes and fetched data; `.gitignore`d as compiler output |
| **Page** | a docs showcase that attaches a corpus by name and mounts a dashboard and Ask on it, with the docs' local model |
| **Runner** | a Vitest project beside `@kanzo-tech/testing`'s end-to-end one: Playwright's Chromium, `getHarness` on `AnswerHarness`, `DashboardHarness` and `FilterBarHarness`, `expect.poll` and no fixed wait |
| **Model** | the real one, on the machine's GPU through WebGPU — live, never replayed, never the double: what is measured is the model |
| **Results** | one line per case in `packages/ai/eval/results/<model>/ask.jsonl`, `.gitignore`d; a case that fails is a result, and the run fails only when it cannot ask |
| **When** | by hand, `pnpm --filter @kanzo-tech/ai eval`, before a change to Ask or to the model; never in `pnpm verify` and never on CI, which has no GPU |

The set is data apart from its runner, so the second runner [Tasks](/docs/design/tasks#everything-in-the-browser-the-model-too)
names — the same weights on native llama.cpp in CI — reads the same cases when it is built.

**What would reverse it:** a second product's evaluation set over Ask with cases of its own — then
the runner is the shared part, and each product keeps its cases.
