The family is nine packages that import each other in one direction and agree on that by
convention. `theme`, `mosaic`, `llm`, `auth` and `navigation` sit at the bottom, `ui` over them, and
`ai` and `graph` over `ui`. No import cycle exists. Nothing walks the edges, so nothing would notice
one, and the sentences that describe the direction have already been wrong once. This page says what
the direction is, what the lowest layer holds, which rule governs each seam between two packages, and
which guard holds each rule.

<Callout type="warn">
**Status: to be built.** The layer map, the kernel, the split of `mosaic` and the guards below are
decided and not yet in the tree. Where this page and the tree disagree the tree wins, and the
disagreement is the work. *Breaking*, at the end, lists the changes in a consumer's words; the
pages named there carry the rest.
</Callout>

## Five layers, imports point down

| Layer | Holds | Imports |
| --- | --- | --- |
| **L0** | `@kanzo-tech/kernel` | nothing |
| **L1** | `theme`, the `@uwdata/*` door (`@kanzo-tech/mosaic`), `llm`, `auth`, `navigation` | L0 |
| **L2** | the engine (`@kanzo-tech/mosaic/engine`), `@kanzo-tech/relations` | L0, L1 |
| **L3** | `ui` (its root, `/table`, `/editor`) | L0, L1, L2 |
| **L4** | `ai`, `graph`, `ui/analytics` | L0 to L3, and the edges named below |

**A package imports only from a lower layer.** The same layer is a sibling, and a sibling edge exists
only where this table names it: `ai/data` reads `ui/analytics`, and `graph` reads `ui/analytics`.
Nothing else at L4 reaches sideways, and nothing at any layer reaches up. `@kanzo-tech/testing` is
outside the map: production code imports nothing from it, and only a `./testing` entry or a test
imports it.

**The layer belongs to an entry, not only to a package.** A package's `exports` map spans layers
when its entries have different reasons to exist: `mosaic` is the door at its root and the engine at
`/engine`; `ui` is the design system at its root and a Mosaic client at `/analytics`. Each package
declares one `kanzo.layers` field in its own `package.json` mapping each entry to its layer, so the
table above is derived from the manifests and has no second copy.

**Why five, and not the concentric circles.** Cockburn's hexagon names *ports* defined by the party
driving the conversation, and Martin's rule is that source dependencies point inward and what crosses
is "isolated, simple, data structures" (both read). Both reduce here to a direction and a shape for
what crosses a seam, and four or five bands carry that. A finer ladder would be a taxonomy nobody
could test; each band here is tested by one import walk.

**What it deletes.** The sentence in the philosophy page that said `ui` "depends on none of" its
sibling packages. It was false by the manifest: `ui` depends on `@kanzo-tech/theme` and declares
`@kanzo-tech/mosaic` as an optional peer, because `ui/analytics` is a Mosaic client. The philosophy
page now states the narrower rule, and the guard below asserts it: **`ui` imports only a lower layer
(`theme` everywhere, the `@uwdata` door from `/analytics` alone), never `graph`, `ai` or any package
beside it, and nothing at a lower layer imports `ui`.** The first draft of this rule said `ui`'s root
imports no sibling; that was false too, since the root imports `theme`, which is why the sentence was
written against the manifest and not from memory.

**What would reverse it.** A second package that needs to import upward and cannot be moved: a layer
whose members all import one another. Then the layers are not layers, and the guard becomes an
allow-list of edges with no table above it. Until then the ladder costs one field per manifest.

No test holds this yet; the package-layers guard, below, is to be added.

## The kernel holds what four packages each wrote

`@kanzo-tech/kernel` has no dependency, no peer, no React, no DOM and no side effect at import. It
holds the five things that two or more packages already define for themselves, and nothing else.
It is the family's counterpart of OpenTelemetry's API package: library code imports a small package
with nothing behind it, and the application owner installs an implementation (the overview, read:
"Instrumentation authors MUST NOT directly reference any SDK package"). The budget is about three
hundred lines, held by a gauge of its own.

| Piece | Is | Replaces |
| --- | --- | --- |
| `Problem`, `isProblem` | the one error class, in the shape of RFC 9457's problem details: `code`, `title`, `detail`, `data`, `cause`, `help`, `related`, `severity`; and the structural predicate that narrows an `unknown` | `EngineError` in `mosaic`, `GraphError` in `graph`, `LlmError` in `llm`, `AuthError` in `auth`, and the regex in `ui`'s `Problem` composite |
| `within` | the bounded wait: `within(ms, work, { signal })`, rejecting with a `Problem` on `AbortSignal.any` composition | the 60 s timer in the engine boot, the 30 s `deadline.ts` in `auth`, the 10 s timer in `graph`'s renderer |
| `Queryable` and its Arrow-like `Table`, `Vector` | the read-only port: `query(sql, { signal })` resolving to columns | `Table` and `Vector` in `mosaic`, `Answer` in `graph`, the `Pick<Engine, "query">` in `ai/data` |
| the disposal convention | a `Disposable` type and the symbols `Symbol.dispose` and `Symbol.asyncDispose` for every handle a caller must give back | `release` and `serial` in the engine, each package's own unsubscribe closure |
| `mark` | `mark(name, start, detail?)`: a `kanzo:`-prefixed `performance.measure` and nothing more | the `kanzo:llm:*` spans written by hand in `llm` |

Each piece has its rule, its motivating failure, its reference and its reversal on
[the kernel page](/docs/design/kernel) and nowhere else: [`Problem`](/docs/design/kernel#problem),
[`within`](/docs/design/kernel#within), [`Queryable`](/docs/design/kernel#queryable) (whose contract
is [the engine's](/docs/design/engine)), [disposal](/docs/design/kernel#disposable) and
[`mark`](/docs/design/kernel#mark). What this page adds is the direction: every package may import
the kernel, the kernel imports none of them, and the registry of codes the one class carries is
[the failure page's](/docs/design/failure#the-registry-is-generated).

## The seams, one rule each

A *seam* is any place two packages, or a package and its host, meet. Each has one rule and one place
the rule is written.

| Seam | The rule | Owner |
| --- | --- | --- |
| a failure crosses a package | a `Problem`, thrown whole, `area/kind` | [kernel](/docs/design/kernel); [failure](/docs/design/failure) |
| a wait | `within`, by the party that makes the request, once | kernel; [failure](/docs/design/failure) |
| a read of the database | `Queryable`, and an abort **interrupts the statement** in the engine; an adapter that cannot says so and fails loudly | kernel type; [engine](/docs/design/engine) |
| a lifecycle | the dispose symbols | kernel |
| a library reads data | a query on the host's client | [reads](/docs/design/reads) |
| the engine reaches a chart or a graph | the page provides `engine` once, through `@kanzo-tech/mosaic/react`, and every view reads it and the page's selection from there; the coordinator is the engine's internal cache and no component accepts one | [engine](/docs/design/engine#the-page-provides-the-engine-once-and-every-view-reads-it-from-there); [analytics](/docs/design/analytics), [graph](/docs/design/graph) |
| a catalog becomes a model | `JoinGraph` is the one read-model; a reader is a typed `CatalogReader` taking a `Queryable` | `relations` |
| a model | the AI SDK's `LanguageModel`, with its middleware as the extension point; one registry | `llm`; [ai](/docs/design/ai) |
| an identity | the `Auth` port with a `SessionStore`; a server door that reaches no React | `auth`; [auth](/docs/design/auth) |
| a router | the root knows none; a subpath adapts one | `navigation`; [navigation](/docs/design/navigation) |
| an optional dependency | a subpath for the engine that needs it, per entry, never the root | [naming](/docs/design/naming), the guard below |
| a test seam | the double goes through the registry production uses; production ships no probe | [testing](/docs/design/testing) |
| a global | one documented owner per global; a new one is a design decision | the guard below |

The row that moves most is the engine. `mosaic` carried five reasons to change in about fifteen
hundred lines, so it splits where those lines run: the door stays `@kanzo-tech/mosaic` at L1, the
engine is `@kanzo-tech/mosaic/engine` at L2 with the DuckDB-WASM dependency declared for that entry
alone, and the model, the crossfilter and the words move to `@kanzo-tech/relations`. The reasoning for
each part, and the rule that an abort interrupts the statement, are [the engine's](/docs/design/engine)
and [relations'](/docs/design/relations); the layer is this page's.

**What would reverse the seam rows.** A row that no host ever branches on, which folds into its
neighbour; and a second implementation of one row that cannot honour its rule, which makes the
rule a conformance test and not a sentence. The table is the roster; `ls` of the guards is the
check that it has not grown a row without one.

## The catalog is a port, and it was not named

The only constructor of a `JoinGraph`, which `ui/analytics`, `ai/data` and `graph` all consume,
lived in `graph`, the heaviest of the three: a host that wants a dashboard and no canvas installed
`@kanzo-tech/graph` and `@cosmos.gl/graph` to build a model. The model sat below the code that builds
it, and the relation names a catalog is read from were swapped for another producer's in exactly one
function between two releases, which measures that the seam is real and single and shows it was typed
nowhere. It is typed now: a `CatalogReader`, in `relations`, whose rule and reversal are
[that page's](/docs/design/relations#a-catalog-is-read-by-a-catalogreader).

## Packaging follows the entry

npm peer declarations are per package, not per entry. `ai/task` imports only `llm` and the AI SDK, its
file says "No React and no tools", and the package declares `@kanzo-tech/ui` and `@ai-sdk/react` as
required peers, so the headless task runtime cannot be installed without the design system. The same
shape had `graph` requiring a WebGL renderer for a model builder and `mosaic` a database for a
crossfilter.

The rule is that **an entry's static closure reaches only the peers that entry declares**, and a
package declares them in `kanzo.entryPeers`, a map from entry to the peers it needs. A peer that every
entry needs is required; a peer that only some need is optional in `peerDependenciesMeta`, and the
map says which entries need it. `ai` therefore makes `@kanzo-tech/ui` and `@ai-sdk/react` optional
peers with `./task` needing neither. It extends what the root-only guard already asserts: an optional
peer is reached from no root entry. A TanStack Query listing (read) shows the core as its own
package, `query-core`, and Zag ships each machine as a package (intro, read). The family does not
split the headless cores into packages: it has one adapter, React, and the layer guard makes the split
real in a directory. It takes the packaging half, which is to say which peer which entry pulls.

**What would reverse it.** A non-React consumer of `ai/task` or `graph/core`: an evaluation runner in
Node, a worker. Then the core is a package, because a peer map cannot give a consumer a version of its
own. Today the evaluation harness imports `ai/task` from a React app only.

*Held by* `packages/ui/src/optional-peers.test.ts`, "are reached from no package's root entry",
for the root entry. Every other entry is to be added with the entry-peers guard, below.

## Names

[Naming](/docs/design/naming) owns what an *export* is called. This section owns the names above
it: packages, entries, directories, files and the words the tree uses for itself.

**A package is named for the job it does for a host, or for the one reference it speaks.**
`@kanzo-tech/mosaic` keeps its name: it is Mosaic's conversation with nothing hidden, and calling it
`data` would turn a reference a reader can look up into a box they cannot open.
`@kanzo-tech/navigation` becomes **`@kanzo-tech/navigation-guard`**: its documentation already says
so, because `navigation` is also one of `ui`'s component categories, and the sidebar showed two
groups with one word. *What would reverse it:* the package taking a second navigation job that is
not a guard.

**An entry, its directory and its docs group share one name.** An entry is `src/<entry>.ts` or
`src/<entry>/`, and nothing else in the package is called that.

| Was | Becomes | Why |
| --- | --- | --- |
| `ui/analytics` over `charts/` | `analytics/` | one thing had two names |
| `ui/table` over `table/` | `ui/data-table`, `data-table/` | the root also ships `Table`, the simple one |
| `ui/editor` over `CodeEditor.tsx` | `ui/code-editor`, `code-editor/` | the entry holds one editor and should say which |
| `graph/section` | `graph/prefs` | see *section*, below |
| `next-*.ts` in `auth` and `navigation-guard` | `next/` | a filename prefix doing a directory's job |

A docs group documents one package and carries its name. `ui`'s components alone are grouped by
Shark's categories, because a reader looks for a dialog, not a package. *What would reverse it:* an
entry whose code cannot live in one place.

**Every file is kebab-case**, as every file in Shark's registry is; thirteen are not
(`CodeEditor.tsx`, `KanzoThemeProvider.tsx`, `sortableHeader.tsx` among them). The philosophy page's
naming rule speaks of *export* names — a vendored primitive and the convenience built on it — and no
longer claims a meaning for file case, which the files never kept: `composites/` held seven of each.
*What would reverse it:* nothing measurable; it is the reference's spelling.

**A relative import names the emitted file, `./button.js`.** `mosaic` and `llm` are built by `tsc`
for Node's ESM, where nothing else resolves, and the Bundler resolution everything else typechecks
under accepts it. Both spellings were in use, sometimes in one file. A lint rule holds it and its
fix migrates the rest. *What would reverse it:* TypeScript rewriting extensions in every build.

**One word, one meaning in the tree**, as [naming](/docs/design/naming#one-name-one-meaning-in-every-barrel)
already requires of exports:

- **section** is the [layout region](/docs/layout/section). A package's block of preferences was a
  section too — `SectionManifest`, `SectionProvider`, `GRAPH_SECTION`, `graph/section` — while the rest
  of that family said *pref*: `Pref`, `CORE_PREFS`, `useGraphPrefs`. It becomes **prefs**:
  `PrefsManifest`, `PrefsProvider`, `GRAPH_PREFS`, `graph/prefs`. *What would reverse it:* a block of
  preferences drawn by `SectionRoot` as one thing.
- **testing** is the package; a directory of doubles is `test/` (below).
- **example** is a file in `docs/examples/`. The world those files draw from is `docs/guild/`, after
  the Guild it describes; `docs/example/` was one letter from `examples/`.

## Places

**Inside a package, a directory is an entry.** For `ui` that reads, as Shark's registry does:

```
packages/ui/src/
├── index.ts         components/  hooks/  theme/  lib/
├── analytics.ts     analytics/
├── data-table.ts    data-table/
├── code-editor.ts   code-editor/
└── tailwind.css
```

`components/` is flat. `hooks/` holds the public hooks, `lib/` only what no entry exports, `theme/`
the appearance plane's React adapter. The three size layers stop being directories: `simples/`,
`composites/` and `layouts/` described about half of `src/`, and about fifteen files failed their own
layer's test — `command` and `FacetFilter` are assemblies, `float` and `resizable` position things,
`show` and `locale` render nothing, `sidebar-cookie` is a parser. Shark keeps every one of those in
one `components/`, and since the barrel is flat no consumer ever saw a layer.
[The taxonomy test](/docs/philosophy#the-taxonomy-test) stays what it already said it was: prose that
places a decision, not a file. Every other package keeps the directories its design page argues for —
the graph's copy a stated reference per layer — under two rules: the entry rule above, and **the tree a
design page draws is the tree on disk**. *What would reverse it:* readers who search a package by
something other than its entries; Shark's registry is the evidence that they do not.

**A unit test sits beside its file; what tests need lives in `<package>/test/`, outside `src/`.**
Fakes, fixtures, sample data and the runner's setup sat in five shapes — `ai/src/testing/` (the Nobel
and SNB samples among them), `auth/src/test/`, `graph/test/`, `ui/test/` and a `.fixture.ts` suffix in
`navigation`. Outside `src/` they need no build exclusion and cannot ship. What every suite repeats —
the jsdom shims, booting DuckDB in Node, the harness hook — is `@kanzo-tech/testing`'s; `ui` and `ai`
had byte-identical setups. *What would reverse it:* a double a consumer must import; then it is
`@kanzo-tech/testing`'s API.

### Repo-wide guards live in a workspace of their own

**A guard that reads more than one package lives in `guards/`, a private workspace beside `docs/`,
with `guard-corpus.ts` and its data** (`shark-surface.json`, the parity tables). At the root of
`ui/src` they read `ai/src`, `docs/` and other packages' `dist/` that `ui` never declared, sat among
`ui`'s entries, and `guard-corpus.d.ts` shipped in `ui`'s tarball. A workspace declares what it reads
and publishes nothing. **A rule decided by reading one file is a lint rule** — a class list, a
comment, a specifier, a literal hue — so the linter owns walking, parsing and comments; four guards
had each written a `stripComments`, in two behaviours. A rule about the set — the barrel against
Shark, a page's evidence, a token against every theme, the layer walk — is a guard. A guard about
one package's own files stays beside them. *What would reverse it:* a guard that only means
something inside one package.

**Every package has one shape**: a README, a `vitest.config.ts`, a `size` budget and the same script
names. `tsc` builds a package with no React and no stylesheet, vite the rest — the one difference
with a reason. A guard reads every manifest against that list, and a package that differs says why
beside the field. *What would reverse it:* a field that means nothing for one package, which says so
where the field would be.

**In `docs/`, one place per kind of thing.** Page, example, showcase and offered tool are
`docs/CLAUDE.md`'s. Two kinds lived there unnamed: a **fixture** — a page that exists for a check,
`app/fixtures/` — whose check runs in CI or the page goes; and **data** — `docs/guild/`, where every
helper that builds or serves example data lives, none in `examples/` or `lib/`. `examples/` holds
`example-*.tsx` files with a default export and nothing else. *What would reverse it:* a third kind
that is neither, which gets its own name here.

## Constants

**A constant's home is decided by who changes its value, and casing is not the question.** Whether
it is spelled `SIDEBAR_WIDTH` or `sidebarWidth` says nothing about where it belongs; renaming one to
the other, or inlining it at its only use, moves no decision. What does is asking who would edit the
number, and putting it where that person edits things.

1. **The consumer changes it → it is configuration.** A token in `tokens.css` when a theme or a
   stylesheet sets it (`--selection`, `--size-control-min`, `--sidebar-width-mobile`), a prop with a
   default when it is per instance (`SidebarProvider`'s `hotkey`), the provider or a pref when it is
   per person, and `translations` when it is words a reader sees (`Tool`'s state labels,
   `PromptInputSubmit`'s *Send*, *Stop* and *Retry*). It is never an exported constant the consumer
   cannot reach.
2. **A format or a protocol changes it → its owner declares it once**, and every reader imports it. A
   column name, a header, a breakpoint: `useIsMobile` reads Tailwind's `--breakpoint-md` off the page
   instead of copying 768, and `Chat` asks `Tool`'s table which states are still working instead of
   restating three of them. A table is generated from its source or is the source; the obligations of
   `theme` and `graph` are two module-local tables in one shape, `Obligation`, graded by one function,
   `gradeObligations`, declared in `theme` — the lowest package the two import.
3. **Nobody changes it → it is private**, a module-local name or a literal at its only use. It is not
   exported for a test: a test asserts through behaviour, so `ALT_ROWS` and `CHART_CAPACITY_PROPERTY`
   are module-local and their tests count rows and read the property.

**Measured on the tree this was written against**, by every top-level `const` whose name is upper
case in a shipped `packages/*/src` file, typed (`const X: T =`) or not: 319, 68 of them exported and
81 a bare number. Seven values are still declared twice under one name — `KEY = "dense_id"`,
`VERTEX_INDEX` and `VERTICES` in `graph/core/source.ts` and `relations/graphar.ts`, `SERIES_LIMIT` and
`FACET_LIMIT` in `chart-card.tsx` and `dashboard-spec.ts`, `DEPTH = 8` in the kernel's `problem.ts` and
`ui`'s, and the never-aborting `UNSTOPPED` signal in `graph` and `ui` — each a fact or a limit with
one owner that has not been chosen yet. `ENGLISH` in 26
files is not a duplicate: it is each component's own default for its own `translations`.

**Nothing checks this yet**, and the counts above are a grep, not a guard: whether a value is a
consumer's, a format's or nobody's is a judgement about who edits it, which no scan reads off the
source. What a guard could hold is the narrow half — the same value under one name in two shipped
files, and an export whose only importer is its own test — and it is not written.

*What would reverse it:* a value two packages must agree on and neither owns, which is declared by the
lowest package both import — the rule applied rather than broken; or a consumer who needs to change a
value classified as nobody's, which moves it to the first kind, not to an exported constant.

## What dies

- **The test probes that ship.** `charts/testing-probe.ts` in `ui` and `parts/testing-probe.ts` in
  `graph` were seams in production source reading a global that production "never defines",
  `window.__KANZO_TESTING__`. `llm/local` had already removed that pattern and written the reason. Both
  probes are deleted, and the global with them: Plot puts `scale(channel)` on the output it returns,
  so `ChartHarness` reads it off the DOM, and `GraphCanvas` does the same with the live answer a
  WebGL canvas alone holds — `screenOf(vertex)` and `screenAt({ x, y })` on its element, in every page
  ([Testing](/docs/design/testing#a-canvas-says-where-it-draws-on-its-element)). **What would
  reverse it:** an assertion that needs a live object no element of the component can carry.
- **`EngineError`, `GraphError`, `LlmError`, `AuthError`**, and `auth/src/deadline.ts`, the 10 s timer
  in `graph`'s renderer and the engine's `abandon`: replaced by `Problem` and `within`.
- **The four definitions of the engine's table type** and the `Pick<Engine, "query">` in `ai/data`.
  `LocalModelRegistry`, declared twice, once structurally in `testing`.
- **`Engine.coordinator` as a public field and `registerFileBuffer` in the port** consumers see.
- **`ai`'s required peers on `ui` and `@ai-sdk/react`** for `./task`.

## The guards

All are specified in [`guards/`](#repo-wide-guards-live-in-a-workspace-of-their-own), over
`SHIPPED` from `guard-corpus.ts`, never copied into a second package — or, where the rule is decided
by reading one file, as a local lint rule: `one-deadline` and `no-ambient` are that kind. Each says
what it cannot prove. None exists
yet, so no *Held by* line cites one by title, and `documented-evidence.test.ts` will not accept a
citation until it is a real `it()`.

| Guard | Asserts | Cannot prove |
| --- | --- | --- |
| `package-layers.test.ts` | the layer table is derived from `kanzo.layers`; every static import in a shipped `src/` is of a lower layer or a named sibling edge; `@kanzo-tech/ui` is imported from no layer below L3 | dynamic `import()` and type-only imports, as `optional-peers.test.ts` skips them; a re-export through a workspace alias |
| `entry-peers.test.ts` | the static closure of every `exports` entry reaches only the peers `kanzo.entryPeers` lists for it; replaces the root-only walk in `optional-peers.test.ts`, which is deleted when this lands | a peer reached only by a dynamic import |
| `one-failure-model.test.ts` | every class extending the built-in Error in `SHIPPED` is the kernel's `Problem` or on a short allow-list, and the count of plain `new Error(` per file may not rise | a failure thrown by a dependency; a `Problem` built with a wrong code; that a plain error is a fault and not a condition |
| `one-deadline.test.ts` | no `setTimeout(` whose callback aborts or rejects, outside the kernel | a wait built on `setInterval` or a promise race; fossil holds the same rule with a lint rule in its own repo |
| `no-ambient.test.ts` | `Symbol.for(`, `globalThis` and `window.__` appear only in the files that own a documented global: the engine, the local-model registry, the testing hook | a global assigned through a computed key |
| `client-boundary.test.ts` widened | the corpus becomes every package that declares `react` as a peer, not those that declare `tailwind-variants`, closing the hole [the auth page](/docs/design/auth) names | a directive that survives the source but is lost in `dist/`: only the docs build evaluates that |
| `stale-citation.test.ts` | every backticked repository path in a design page resolves in the tree, and no page cites `path:NN`: a line number is a claim about a revision | a path that resolves to the wrong file; a symbol renamed inside a real file |

The last row is the architecture's own: this page cites files and symbols and no line numbers, because
the evidence it was written from was read at one revision and a line number is true only there.

**What would reverse them.** A guard that costs more to keep than the defect costs to fix. The
cheapest to reverse is `no-ambient`: if the allow-list grows past a handful of files the rule is a
list, and the list should be a rule of its own.

## Breaking

- `EngineError`, `GraphError`, `LlmError` and `AuthError` are gone. Catch a `Problem`, or narrow with
  `isProblem`, and read `code`.
- Crossfilter, `JoinGraph`, the relation words and `readJoinGraph` import from
  `@kanzo-tech/relations`, not from `@kanzo-tech/mosaic` or `@kanzo-tech/graph`.
