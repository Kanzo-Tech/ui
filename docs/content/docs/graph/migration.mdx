---
title: Migrating to v0.20
description: What changed in @kanzo-tech/graph for v0.20 — the legend's last line, three parts that moved in from the showcase, and the layout's drag and camera.
---

v0.20 moves three pieces every host was writing into the package, splits the legend's sentence
into a part of its own, and changes what a drag and the camera do while a layout runs. The props of
`GraphRoot` are unchanged.

## `GraphLegend` no longer prints "drawn"

The legend is **the category rows only**. Its last line, "N of M drawn", is gone, and a legend with
no category to key — colour a constant and nothing on `symbol` — now renders nothing instead of an
empty box.

What is drawn of the whole is **`GraphCounts`**, a part of its own so a footer can carry it:

```tsx
// before
<GraphCanvas>
  <GraphLegend className="absolute start-2 bottom-2" /> {/* rows, then "1,203 of 5,021 drawn" */}
</GraphCanvas>

// after
<GraphCanvas>
  <GraphLegend className="absolute start-2 bottom-2" />
</GraphCanvas>
<footer>
  <GraphCounts /> {/* "1.2K of 5K nodes drawn · 8K edges" */}
</footer>
```

The sentence is compact in the nearest `LocaleProvider`'s locale and counts edges too — `Drawn`
gained `edges`, the links whose two ends survive the filter. A host that summed the manifest's
`record_count`s for its footer can delete that code: `GraphCounts` says the same thing, under the
filter.

## The showcase's parts are library parts

The [workspace showcase](/docs/showcases/workspace) wrote three things a host needed and the package
did not have. They are parts now, and the showcase's copies are deleted.

| Before (copy from the showcase) | v0.20 |
| --- | --- |
| `ArchiveSearch` — a `Combobox` over a Mosaic query, one query per keystroke | `GraphSearch` — every drawn vertex's text read once, filtered in the browser, ordered by `r`, picking is `reveal` |
| `GraphAppearance` — named looks in arrangement state, hand-drawn previews, a Camera button | `GraphLooks` — Nebula, Atlas and Ink as presets over `GRAPH_SECTION`'s axes, with the axes under Customize |
| `PreferencesSections namespace="graph"` in a Settings panel | `GraphLooks`, which draws the same axes and the three looks over them |
| a footer summing the manifest | `GraphCounts` |

**A search that ran SQL can go.** A host-written search over the vertex relation — a union of
`ILIKE`s, capped at fifty — is what `GraphSearch` replaces, and it no longer needs a Mosaic query or
the relation's name:

```tsx
// before
<CorpusSearch />   {/* useChartQuery + Query.unionAll(...) + reveal */}
<GraphInspector />

// after
<GraphSearch placeholder="Find anything in the graph…" />
<GraphInspector />
```

**Looks are preferences, not state.** The named look the showcase held in React state is now
derived: `useGraphPrefs()` answers `preset` — `"nebula"`, `"atlas"`, `"ink"` or `null` — from the
resolved axes, and the host keeps only its pairing of looks to channels. `GraphLooks` needs
`GRAPH_SECTION` among the theme provider's `sections`; without it, it renders nothing. The Camera
button is the toolbar's Fit.

## A drag pins only while a layout runs

Dragging a node used to pin it whether or not a layout was running. Now **a drag pins only while a
layout is running or paused**; with no layout running it just moves the node, because a pin nothing
pulls against means nothing. **Release now reheats**: the released nodes flow back, and a paused
layout gets a 1.2 s burst and is paused again. Nothing to change in code; a host whose help text said
"drag pins a node" should say "while the layout runs".

## The layout contracts around the graph, and the camera follows it

A running layout used to pull the graph into a corner of cosmos.gl's square and leave it there. The
corpus's extent is now **centred in the square** it simulates in, and **while a layout runs the
camera re-frames the moving points** every 900 ms and once more when they settle, until the reader
zooms or pans. Fit, after a layout has run, frames where the points are. `GraphCounts spinner` also
spins while a layout runs, labelled "Laying out".

`status` is unchanged — it is the data's, and a layout over a drawn graph is `idle`. A footer that
wants to say "laying out" reads `motion === "running"` and `progress`. See [Layout and
camera](/docs/graph/layout).

## Failures kept whole, everywhere

`GraphSearch` hands a failed read of the names to the root's `onFailure` as the thrown value, and its
input turns `aria-invalid` with "The names could not be read." instead of staying disabled — the same
contract every other part has had since v0.19.
