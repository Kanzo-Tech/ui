## Usage

```tsx
import { DiagnosticList, Problem } from "@kanzo-tech/ui";
```

```tsx
<DiagnosticList>
  <Problem describe={describeCode} error={error}>
    <Button onClick={retry} size="sm" variant="outline">Try again</Button>
  </Problem>
</DiagnosticList>
```

Every library here fails with the same shape: an `Error` with a `code` in `area/kind`, a `title`, a
`message` for a person and the `data` the code carries, with what caused it as `cause`. `Problem`
reads that shape off **whatever was thrown** — it imports none of those classes, so an error from a
library it has never heard of, a server's problem body or an object a stream handed over reads the
same way. A value that is no object is drawn as its own `String`.

## What it reads

| Field | Drawn as |
| --- | --- |
| `code` | The source, in monospace, and `data-code` on the row — what an end-to-end test asserts on. Only a string in `area/kind` counts. |
| `title` | The header's title. Without one, the `message` is the title. |
| `message` | The detail, once the row is open. `detail` is read where there is no `message`. |
| `data` | Nothing — it is handed to `describe`. |
| `cause` | A row nested below, read the same way, and so on down. A coded cause is open; an uncoded one is folded. |
| `severity` | `"warning"` or `"info"` pick the variant; anything else is `"error"`, drawn `destructive`. |
| `help` | A second paragraph under the detail. |
| `related` | Rows beside the cause — the diagnostics a failure carries, such as the ones a program did not compile with. |

The tree stops at a cause it has already drawn, and eight levels down, so a cycle in `cause` draws
once rather than forever.

## The host's words

A code is written for whoever raised it: `archive/silent` says *the archive did not answer*, and the
clerk at the desk wants *the archive is closed*. **`describe(code, data)` is the host's registry**,
called for the problem and every coded cause under it. Return `undefined` to keep the error's own
words, or any of:

- `title` — replaces the title.
- `detail` — replaces the detail, and **the author's row is kept one level down**, so what the
  library said is never lost to what the host prefers to say. `data` is what a detail that names a
  figure is written from.
- `link` — `{ label, href }`, a button beside the details: *Sign in again*.
- `page` — the page that explains the code; the code in the header links to it.

**The page a code links to is yours.** A problem's `type` is a tag URI —
`tag:kanzo.tech,2026:problem/engine/lost` — an identity that cannot be opened, so the library links
nowhere by itself. Where your documentation explains codes, return the page from `describe`, and every
code links to it, the library's and your own:

```tsx
const describe = (code: string) => ({ page: `https://docs.example.com/problems/${code}` });
```

Every `Problem` the library draws for a coded failure takes your `describe` — `Chat`, `ModelBadge`,
`AnswerCard` — so one function is the whole configuration.

The words `Problem` draws itself — the severity badge and the details trigger's name — are
`translations`, in English by default. The two are kept apart on purpose: `translations` is the same
record whatever failed, the one prop every component here takes its words through, and `describe` is
the host's wording of one failure it recognises, resolved from that failure's `data`.

## Accessibility

Each row's details trigger is named by its row — **`Details: <title>`** — because a tree of six
causes is otherwise six buttons all announced as *Details*, with nothing to tell a screen-reader user
which one they are on. `translations.details` takes the title and returns the name.

`Problem` is a list item, as `Diagnostic` is: put it in a `DiagnosticList`, alone or beside other
rows. It is open at rest, because a failure on screen is there to be read; `defaultOpen` and `open`
pass through.

## API Reference

### Problem

`ProblemProps` extends `DiagnosticProps` without `variant`, which the error's severity decides.

| Prop | Type | Default |
| --- | --- | --- |
| `error` | `unknown` — what was thrown | required |
| `describe` | `(code: string, data: unknown) => ProblemDescription \| undefined` | — |
| `children` | `ReactNode` — beside the problem's own link and details trigger | — |
| `translations` | `Partial<ProblemTranslations>` | English |
| `defaultOpen` | `boolean` | `true` |

`ProblemDescription` is `{ title?, detail?, link?: { label, href }, page? }`. `ProblemTranslations` is
`{ destructive, warning, info }` — the severity badge's word per variant — and
`details: (title) => string`.
