title: useCompletion
description: Ghost-text completion that does not own your input's value. It streams a continuation, debounces the request, and hands the string back for you to insert.

## Usage

```tsx
import { useCompletion } from "@kanzo-tech/ui";
```

```tsx
const completion = useCompletion({ complete });

<Input
  value={value}
  onChange={(e) => {
    setValue(e.target.value);
    completion.setValue(e.target.value);
  }}
/>;
```

<Callout type="info">
For a field that should just work — an aligned overlay ghost, `Tab` to accept, `Esc` to dismiss —
compose the **`Complete`** compound instead; see
[AI-assisted fields](/docs/forms/ai). This hook is the headless engine underneath it, for
attaching the same capability to a control the library did not pre-assemble.
</Callout>

## It does not own the text

Your input owns the value. The hook only ever produces a `ghost` — the continuation — and
`accept()` **returns** it as a string for you to insert wherever you want:

```tsx
const accept = () => {
  const text = completion.accept();
  if (text) setValue((v) => v + text);
};
```

That single decision is what lets one hook drive an `Input`, a `Textarea`, an `InputGroup` or an
inline `Editable` without any of them fighting over state. It also means the hook cannot corrupt
your value: the worst it can do is offer a string you ignore.

## Two ways to ask

| Call | Timing | The interaction it models |
| --- | --- | --- |
| `setValue(text)` | after `debounceMs` | the user is typing — coalesce keystrokes |
| `request(text)` | immediately | the user asked — a ✨ button, a shortcut |

Both abort the request in flight first, and both are gated by `minLength`: below it, nothing is
requested and any existing ghost is cleared. That gate is why a field does not fire a request on
its first two characters, where a model has nothing to work with anyway.

## The echo the hook removes

Models frequently restate the whole value before continuing it. If the first chunks repeat the
current text verbatim, that one unambiguous full-value echo is dropped — nothing finer. There is
no character-level overlap matching, because that used to mangle continuations that happened to
begin with the same word the field ended on.

<Callout type="warn">
`complete` must yield the **continuation**, not the rewritten value. Yielding the whole text is
only survivable because of the echo rule above; anything in between — a partial restatement —
lands in the field as duplicated words.
</Callout>

## Cancellation is the point

Every request supersedes the last one. Each run captures its own text and its own signal, so a
stale loop that a newer request replaced discards its trailing chunks instead of writing them
into a value the user has already changed. That only holds if your `complete` honours the
`AbortSignal` — pass it straight to `fetch`, or check `signal.aborted` between yields.

Clear on blur (`clear()`) if a stale ghost hanging around an unfocused field would be confusing;
the example above keeps it so the accept buttons stay reachable.

## API Reference

### Parameters

`UseCompletionOptions`:

| Prop | Type | Default |
| --- | --- | --- |
| `complete` | `(value: string, signal?: AbortSignal) => AsyncIterable<string>` | — |
| `debounceMs` | `number` | `350` |
| `minLength` | `number` | `4` |

### Returns

`Completion`:

| Field | Type | Description |
| --- | --- | --- |
| `ghost` | `string` | The streamed continuation so far |
| `hasGhost` | `boolean` | `ghost.length > 0` |
| `status` | `"idle" \| "streaming" \| "error"` | From the underlying [`useAiStream`](/docs/hooks/use-ai-stream) |
| `error` | `string \| null` | Message when the source threw |
| `setValue` | `(text: string) => void` | Request after the debounce — the typing path |
| `request` | `(text: string) => void` | Request immediately — the ✨ path |
| `accept` | `() => string` | Return the current ghost to insert, then clear |
| `dismiss` | `() => void` | Abort and clear the ghost |
| `clear` | `() => void` | Same as `dismiss` — named for the blur path |

Options are read from a ref on every run, so an inline arrow `complete` does not restart
anything.
