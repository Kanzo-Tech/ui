## Usage

```tsx
import { SidebarUser } from "@kanzo-tech/ui";
```

```tsx
<SidebarFooter>
  <SidebarUser user={user} menuItems={items} />
</SidebarFooter>
```

Render it inside a [`SidebarProvider`](/docs/sidebar): it reads the collapse state
to swap the trigger for a bare avatar, and flips the menu's placement on mobile.

## Log out is a menu item

`menuItems` is the only mechanism. There used to be a second, hard-coded one —
`onLogout` / `logoutLabel` / `confirmLogout`, plus a built-in confirmation dialog carrying
untranslatable English copy — which put an auth flow inside a library whose admission rule
excludes auth. **Those props are gone.** Log out is now an ordinary entry with
`variant: "destructive"` and usually `separatorBefore: true`; the product owns the flow, the
wording and whether there is a confirmation at all.

```tsx
{
  label: "Log out",
  icon: <LogOutIcon />,
  variant: "destructive",
  separatorBefore: true,
  onSelect: () => signOut(),
}
```

## API Reference

| Prop | Type | Default |
| --- | --- | --- |
| `user` | `{ name: string; email?: string; avatarUrl?: string }` | — |
| `menuItems` | `SidebarUserMenuItem[]` | `[]` |
| `linkComponent` | `LinkComponent` | `DefaultLink` |

Initials for the avatar fallback are derived from `user.name`.

### SidebarUserMenuItem

| Prop | Type | Default |
| --- | --- | --- |
| `label` | `ReactNode` | — |
| `icon` | `ReactNode` | — |
| `href` | `string` | — |
| `onSelect` | `() => void` | — |
| `variant` | `"default" \| "destructive"` | `"default"` |
| `separatorBefore` | `boolean` | `false` |

An entry with `href` navigates through `linkComponent`; otherwise it is a plain action item.

## The identity block

`SidebarUser` and [`InstanceSwitcher`](/docs/sidebar/instance-switcher) render the same
avatar-plus-name block in their trigger and in their menu header, extracted as `SidebarIdentity`
so the two cannot drift apart. You will rarely reach for it directly — do so only when you build
a third switcher of your own.

<ComponentPreview componentName="sidebar-identity" fullBleed={false} />

```tsx
<SidebarIdentity>
  <SidebarIdentityIcon><BoxesIcon /></SidebarIdentityIcon>
  <SidebarIdentityText>
    <SidebarIdentityLabel>Kanzo</SidebarIdentityLabel>
    <SidebarIdentityDescription>Owner</SidebarIdentityDescription>
  </SidebarIdentityText>
</SidebarIdentity>
```

`SidebarIdentityIcon` swaps the round avatar for a square tile: round reads as a person, square
as a workspace or org. Use one or the other, not both. `SidebarIdentityAvatar` takes the real
[`Avatar`](/docs/data-display/avatar) parts as children, so an image, initials, a badge or a presence
dot are all available — where an `avatarUrl` + `fallback` pair could only ever produce an
`<img>` and some letters.

### Anatomy

```text
SidebarIdentity
├── SidebarIdentityIcon      (workspaces / orgs)
├── SidebarIdentityAvatar    (people)
│   ├── AvatarImage
│   └── AvatarFallback
└── SidebarIdentityText
    ├── SidebarIdentityLabel
    └── SidebarIdentityDescription
```

### Collapsing

`responsive` and `collapsed` stay props on the root because they are behaviour, and the parts
read them from context rather than having them repeated on each one — which is why the component
is `"use client"`. `responsive` gates the `group-data-[collapsible=icon]` variants: the text
column collapses away and the avatar grows to fill the 32px square. Leave it off for the portaled
menu header, which is never collapsed. `collapsed` is derived from the sidebar state, so
`SidebarIdentityAvatar` does not accept a `size` of its own.

### SidebarIdentity parts

| Part | Renders | Props |
| --- | --- | --- |
| `SidebarIdentity` | `div` | `responsive`, `collapsed` (both `boolean`, default `false`) |
| `SidebarIdentityAvatar` | [`Avatar`](/docs/data-display/avatar) | Avatar's props except `size` |
| `SidebarIdentityIcon` / `SidebarIdentityText` | `div` | that element's props |
| `SidebarIdentityLabel` / `SidebarIdentityDescription` | `span` | that element's props |
