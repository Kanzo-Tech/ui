## Usage

```tsx
import { ThemePicker } from "@kanzo-tech/ui";
```

```tsx
<KanzoThemeProvider>
  <ThemePicker />
</KanzoThemeProvider>
```

It reads and writes `useKanzoTheme()`, so it takes no value and no handler: mount it anywhere under
the provider — a settings page, the [`Preferences`](/docs/layout/preferences) drawer (which draws it
first), a dialog — and it edits the live theme.

## How it works

A theme is one mode, so a person does not choose "a theme" — they choose one for light and one for
dark, and which side to wear. The picker draws exactly that, and **the card is the selector**:

- **Light theme** and **Dark theme** — two cards, side by side, and together one radio group,
  *Appearance*. Clicking a card anywhere but on a swatch wears its side: it writes `appearance`, and
  with it `.dark`. The OS is never asked; the starting side is `light`, or the tenant's
  `policy.theme.appearance.default`.
- **Active** — the worn card is the checked one: a primary border and the badge in its header.
- **Swatches** — each card offers only its own side's themes, as a row of round swatches. Pointing at
  one (or focusing it) **previews** it in that card's `ThemePreview` and name, and nowhere else: the
  page does not change, and leaving puts the card's own theme back. **Clicking** one commits it: the
  theme is filed under the card's side and that side is worn, so choosing a dark theme while wearing
  light switches to dark.

Each side remembers its own theme (`themeByAppearance`), so wearing the other card brings back what
was chosen for it. With no choice stored, each card shows the default pair.

Each swatch is the theme's own `--background` and `--primary` split on the diagonal, painted inside a
scoped `KanzoTheme` — the real tokens, never a copy of their colours — so the row grows by one circle
per theme rather than by one card.

### A subset of themes

The picker offers exactly what the provider's `themes` lists, so narrowing the offer is a prop on the
provider, not on the picker:

```tsx
import { themeIndex } from "@kanzo-tech/theme";

<KanzoThemeProvider themes={themeIndex.filter((t) => t.family !== "lofi")}>
  <ThemePicker />
</KanzoThemeProvider>
```

A list with no theme of one side falls back to offering every theme on that side's card, rather
than drawing an empty row.

### A locked brand

A white-label tenant withholds the theme axis and passes its pair as the default. The picker then
draws its two cards without swatches — choosing a card still picks the side, inside the brand:

```tsx
<KanzoThemeProvider
  defaultTheme={{ light: "acme", dark: "acme-dark" }}
  policy={{ theme: { themeByAppearance: { hidden: true } } }}
  themes={ACME}
>
  <ThemePicker />
</KanzoThemeProvider>
```

Pass the same `defaultTheme` and `policy` to `themeScript`. The whole recipe, including reading the
brand from an instance config, is in [Theming → White-label](/docs/theming#white-label).

## Policy

What draws is decided by the tenant's `policy.theme`:

| `policy.theme` | What draws |
| --- | --- |
| nothing | both cards, as the *Appearance* choice, each with its swatches |
| `appearance: { pinned: "dark" }` or `{ hidden: true }` | only the worn side's card — the pinned (or default) side — with its swatches and no radio. The other side's theme would never be worn, so it is not offered |
| `appearance: { default: "dark" }` | both cards, the dark one checked |
| `themeByAppearance: { hidden: true }` or `{ pinned }` | both cards without swatches — the tenant's default pair, previewed; choosing a card still picks the side |
| both withheld | nothing — `ThemePicker` renders `null` |

## The retired-theme notice

When the user's stored theme is no longer in `themes` — a tenant dropped a family, or the library
retired the theme — the provider clears the choice and the picker shows an *info* alert under its
cards: "Brand updated — “dracula” is no longer offered here. You are seeing the default." It is the
same state, and the same words, [`ThemeNotice`](/docs/theming#retired-themes) toasts; translate both
through `copy.retired`.

## Accessibility

- The two cards are an Ark radio group named *Appearance* (`copy.appearance`). Each card's radio is
  its header, stretched over the card, so the whole card is the click target while no control is
  nested in another. Tab reaches the checked card; arrow keys move between the cards and wear the
  side as they go — the native radio behaviour, kept because wearing a side is the choice itself and
  is undone by the next arrow.
- Each card's swatches are a radio group named by the card's title, with **manual activation**, as
  the WAI-ARIA toolbar pattern runs its radios: Tab enters the row on the chosen swatch, arrow keys
  (and Home / End) move focus and preview the focused theme in the card without choosing it, Enter
  or Space chooses it, and Escape puts the preview back. Choosing on arrow would repaint the page on
  every key press.
- A swatch's accessible name is the theme's label, also its tooltip on hover and focus. The swatch
  circles and the preview are decorative (`aria-hidden`); **Active** is drawn for sight and the
  card's checked state says it to a screen reader.
- The cards sit on a container query, not a viewport one: side by side from a 36rem container,
  stacked in a 384px drawer, with nothing passed down. Swatches wrap, and a long label wraps rather
  than truncating.

## ThemePreview

<ComponentPreview componentName="theme-picker" fileName="example-preview" />

```tsx
import { ThemePreview } from "@kanzo-tech/ui";

<ThemePreview theme="nord-dark" />
```

A miniature app screen — a header with the brand mark and a primary button, a sidebar with its active
row, both inks, and two lines of code in the `--syntax-*` colours — rendered inside a scoped
`KanzoTheme`, so every part reads the theme's real tokens rather than a copy of its colours. It is
what the picker's cards, the [themes catalogue](/docs/themes) and the [generator](/theme-generator)
draw.

Without `theme` it inherits the surrounding cascade — the generator wraps it in an element carrying
an unshipped theme as inline custom properties. It is decorative (`aria-hidden`): whatever offers the
theme names it.

## API Reference

### ThemePicker

`ThemePickerProps` extends a `div`'s props, minus `children`.

| Prop | Type | Default |
| --- | --- | --- |
| `copy` | `Partial<ThemePickerCopy>` | English, below |
| `className` | `string` | — |

### ThemePickerCopy

| Key | Default |
| --- | --- |
| `appearance` | `"Appearance"` — the accessible name of the two cards' radio group |
| `day` | `"Light theme"` — the light side's card |
| `dayDescription` | `"Worn while the appearance is light."` |
| `night` | `"Dark theme"` — the dark side's card |
| `nightDescription` | `"Worn while the appearance is dark."` |
| `active` | `"Active"` |
| `retired` | `ThemeRetiredCopy` — `{ title?, formatDescription?({ theme }) }`, shared with `ThemeNotice` |

### ThemePreview

`ThemePreviewProps` extends a `div`'s props.

| Prop | Type | Default |
| --- | --- | --- |
| `theme` | `string` | inherits the surrounding cascade |
| `appearance` | `"light" \| "dark"` | the theme's own side, read off the provider's `themes` or `themeIndex` |
| `className` | `string` | — |
