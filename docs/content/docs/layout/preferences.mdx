The panel opens on arrival so there is something to look at. Toggle the palette in the corner
to see the rest of it: the drawer is **non-modal** and does not close when you click outside,
so the form behind it stays usable while the theme changes live.

## Usage

```tsx
import { Preferences } from "@kanzo-tech/ui";
```

```tsx
<Preferences hotkey="t" />
```

The all-in-one renders a floating trigger plus the drawer. It writes through `useKanzoTheme`,
which sets `data-*` attributes on `<html>` — that is why every component re-skins, including
Ark's portaled overlays, which render into `document.body` and would miss a wrapper element.
Dark mode is delegated to the appearance controller (next-themes, or the provider's fallback).

The panel is deliberately **non-modal** and does not close on outside interaction: you keep
using the app while it re-skins live behind the drawer, which is the only way to judge a theme.

There is no default hotkey. `hotkey` registers a bare, unmodified key on `window` (ignored
while you are typing in a field), and a design system must not claim one in its host's keymap
without being asked.

## Anatomy

```text
Preferences.Root
├── Preferences.Trigger
└── Preferences.Panel
    ├── Preferences.Accent
    ├── Preferences.Base
    ├── Preferences.Radius
    ├── Preferences.Font
    ├── Preferences.MonoFont
    ├── Preferences.Density
    └── Preferences.CopyTheme
```

`Panel` renders the canonical product set when given no children. Pass children to choose your
own — `Base` is omitted from the default panel because most products want one fixed neutral
canvas.

## Choosing the sections

`Panel` renders the canonical set when given no children. Pass children to choose your own — and
the pinned Reset · Copy · Done footer stays. A typography-only panel, for instance: the two font
axes over the neutral base. Same real drawer, floating over the page, in its own viewport.

<PreviewIframe className="h-[42rem]" name="preferences-fonts" source="preferences/fonts" title="Typography preferences" />

```tsx
<PreferencesRoot hotkey="t">
  <PreferencesTrigger />
  <PreferencesPanel title="Typography">
    <PreferencesFont />
    <PreferencesMonoFont />
    <PreferencesBase />
    <PreferencesCopyTheme />
  </PreferencesPanel>
</PreferencesRoot>
```

<Callout type="warn">
Use the **flat** parts (`PreferencesFont`), not the `Preferences.Font` statics. The namespace is
built with `Object.assign`, and statics are lost when a module becomes a client reference under
RSC — `Preferences.Font` reads back as `undefined` there. We hit this for real.
</Callout>

## Extending the panel

The children are yours, so a product can lead with its **own** preferences and then fall back to
the library's theme axes — one drawer, product prefs and theme prefs together, all live. Here a
product `Sidebar side` control sits above the theme sections. This is the move the
[metadata-form showcase](/docs/showcases/metadata-form) uses for its Layout picker.

<PreviewIframe className="h-[42rem]" name="preferences-extended" source="preferences/extended" title="Extended preferences" />

```tsx
<PreferencesRoot hotkey="t">
  <PreferencesTrigger />
  <PreferencesPanel>
    {/* the product's own section, on top — the extension point */}
    <PreferencesField label="Sidebar side">
      <SegmentGroup value={side} onValueChange={(d) => d.value && setSide(d.value)}>
        <SegmentGroupItem value="start">
          <SegmentGroupItemText>Start</SegmentGroupItemText>
        </SegmentGroupItem>
        <SegmentGroupItem value="end">
          <SegmentGroupItemText>End</SegmentGroupItemText>
        </SegmentGroupItem>
      </SegmentGroup>
    </PreferencesField>

    {/* the library's theme axes, flat, below the product's (appearance lives in the header) */}
    <PreferencesAccent />
    <PreferencesRadius />
    <PreferencesDensity />
  </PreferencesPanel>
</PreferencesRoot>
```

## Sections in your own page

Every section is exported flat, so the same controls can live **inline** in a product's own
settings page instead of the floating drawer — they edit the same live theme either way. `Base`
tints the whole neutral canvas: the preset swatches select a curated 50→950 scale, any other
colour tints the neutral ramp toward it.

```tsx
<div className="flex w-80 flex-col gap-6">
  <PreferencesAccent />
  <PreferencesBase />
  <PreferencesRadius />
  <PreferencesFont />
  <PreferencesMonoFont />
  <PreferencesDensity />
  <PreferencesCopyTheme />
</div>
```

`CopyTheme` emits the current selection as a paste-ready `:root` / `.dark` CSS showcase — the
handoff from picking a theme to committing one.
