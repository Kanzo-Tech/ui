title: Showcases
description: Whole arrangements built from the library — the specific shapes that are examples, not components.
full: true
---

A showcase is an arrangement someone actually builds: an application shell, an IDE workspace.
They are **examples, not components**, and that distinction is the point.

The library ships a generic vocabulary — regions, sections, controls. A specific arrangement of
them does not have to become a component; it has to become an example. A whole shell that *is* a
component reads as the product it was extracted from rather than as a design system, and it makes
the library bigger without making it able to build more. This is
[where specificity is allowed to live](/docs/philosophy#where-specificity-is-allowed-to-live).

Each renders in its own viewport, because a shell judged inside a 450px centred box tells you
nothing.
