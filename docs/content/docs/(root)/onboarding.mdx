title: Onboarding a tenant
description: Write a theme, ship the file, let an attribute choose — the work you do once per client.
---

There are two onboarding pipelines and they are easy to confuse, so this page is only the second
one.

**[Installation](/docs/installation) is per product, once**: the packages, the stylesheet, the
provider, the pre-paint script. **This is per client, once**: you write their theme, it ships as a
file, and every surface the client ever sees is a reading of it.

A theme is a block of CSS somebody writes; nothing derives it ([colour](/docs/design/colour) has
the measurement behind that). **What you gain is that a theme is legible, pasteable and diffable.
What you take on is contrast: nothing derives an ink for you.** The last section says what still
checks you.

## Write the theme

A family is two files, one block and one mode each — or one family edited together in the
[theme generator](/theme-generator), which hands you both blocks. By hand: copy the nearest shipped
pair out of `@kanzo-tech/theme/themes/` and change the colours.

```css title="themes/acme.css"
/* @family acme
   @label Acme */
[data-theme="acme"] {
  color-scheme: light;

  /* The twenty-one. Everything else in the vocabulary is a USE of one of these. */
  --background: #fbfcfd;   --foreground: #10151c;
  --card: #ffffff;         --muted: #eef1f5;
  --muted-foreground: #4a5464;
  --primary: #1f6feb;      --primary-foreground: #ffffff;
  --secondary: #e3e8ef;    --secondary-foreground: #10151c;
  --accent: #d6dde7;       --accent-foreground: #10151c;
  --destructive: #d61f27;  --destructive-content: #fff8f7;
  --info: #1155cc;         --info-content: #f7fafe;
  --success: #08794f;      --success-content: #f4fbf8;
  --warning: #b45c00;      --warning-content: #fffaf5;
  --border: #c2c9d4;       --ring: #1f6feb;

  /* Shape. These are what let a client look different without looking like a fork. */
  --radius-box: 0.75rem;   --radius-field: 0.5rem;  --radius-selector: 0.25rem;
  --size-field: 0.25rem;   --size-selector: 0.25rem;
  --stroke: 1px;           --relief: 0;

  /* Read with no fallback by the components, so every theme writes them. */
  --input: #7a8496;        --field: #ffffff;         --faint: #586274;

  /* The editor's inks — AA on --background and on --muted. */
  --syntax-keyword: #7c3aed;  --syntax-string: #0b7a4b;   --syntax-number: #b54708;
  --syntax-function: #1d4ed8; --syntax-variable: #10151c; --syntax-property: #0e7490;
  --syntax-type: #9a5b00;     --syntax-annotation: #c11574;

  /* Optional: the categorical set. Omit it and the theme inherits the default eight; a theme
     that DECLINES the channel says so with --chart-capacity: 0. */
  --chart-1: #1f6feb;      /* … through --chart-8 */
}
```

Dark is a **second theme**, not a second block:

```css title="themes/acme-dark.css"
/* @family acme
   @label Acme Dark */
[data-theme="acme-dark"] {
  color-scheme: dark;
  /* …the same twenty-one, chosen for a dark ground. */
}
```

<Callout type="warn" title="Twenty-one carry a value; nothing else does">
  Do not write the card ink, the sidebar brand or the other names bridged in `tokens.css`.
  They are *uses* of the twenty-one and are declared once, centrally — writing them again in a theme
  is the duplication the whole layer exists to prevent. Override one only when this theme genuinely
  wants it different, which is a decision, not a default.

  `--secondary-foreground` and `--accent-foreground` are in the vocabulary, not expected: a theme
  that leaves them out wears `--foreground` on those fills, and only a theme whose secondary and
  accent are strong fills needs an ink of its own. `--popover` is the same, and in practice only a
  dark theme wants it.
</Callout>

## Ship the file

Add it to the catalogue and regenerate:

```bash
pnpm --filter @kanzo-tech/theme gen
```

That reads the `themes/` directory, writes the `@import` list into `themes.css` and records each
theme's `color-scheme`, `@family` and `@label` in `theme-data.json`. **Adding a theme is adding a
file** — nothing lists them twice — and a family without exactly one light and one dark theme is
refused.

An instance that is not this repository ships the same CSS as configuration instead: the
generator's *Instance config* tab is a `branding: { theme_css, families, default, lock }` snippet,
which the host inlines and maps onto the provider's `themes`, `defaultTheme` and `policy`.

## Decide what this client's users may change

A tenant policy is keyed by namespace, and the core answers to `theme` like any other section. Pin
what the client insists on and withhold the control:

```tsx
const ACME: ThemeOption[] = [
  { value: "acme", label: "Acme", dark: false, family: "acme" },
  { value: "acme-dark", label: "Acme Dark", dark: true, family: "acme" },
];
const policy = { theme: { themeByAppearance: { hidden: true }, radius: { pinned: "sm" } } };

<KanzoThemeProvider defaultTheme={{ light: "acme", dark: "acme-dark" }} policy={policy} themes={ACME}>
// …and the same `defaultTheme` and `policy` to `themeScript`, or the first paint disagrees.
```

A withheld theme leaves the pair to the tenant, so `ThemePicker` offers the theme mode and nothing
else. That is the white-label case working, not a control failing.

## Offer the choice, if there is one

```tsx
<KanzoThemeProvider themes={[...themeIndex, ...ACME]} onThemeRetired={(name) => notify(name)}>
  <ThemePicker />
</KanzoThemeProvider>
```

[`ThemePicker`](/docs/layout/theme-picker) draws a day group and a night group — because a theme *is*
a side — and each card is a `ThemePreview`, the theme painting a miniature screen, so the preview is
the real thing rather than a strip of swatches.

## Verify

**Contrast is checked against one list.** `CONTRAST_PAIRS` in `@kanzo-tech/theme` names every pair a
theme owes and its WCAG floor — inks at 4.5:1, the syntax inks on the page and the active line, the
brand fill, ring, field border and chart slots at 3:1 — and `auditContrast` returns what a theme
fails. `themes.test.ts` holds every shipped theme to it; the generator shows the same findings live.
A theme of your own runs through the same function:

```ts
import { auditContrast } from "@kanzo-tech/theme";

auditContrast((token) => acme[token]); // [] when every pair clears its floor
```

Then look at it. Set `data-theme` on `<html>` in the docs and read a real screen.
