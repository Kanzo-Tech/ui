A theme is one mode, so the library ships **families**: a light theme and a dark one that belong
together, the pair a user wears by day and by night. Four ship, and `kanzo` is the default:

| Family | Day | Night | Source |
| --- | --- | --- | --- |
| `kanzo` | `kanzo` | `kanzo-dark` | the brand at [kanzo.tech](https://kanzo.tech): deep green `#004011` by day, neon `#1AE973` by night, mist `#E0E7DF`; Geist for the commercial Neue Haas Grotesk |
| `catppuccin` | `catppuccin-latte` | `catppuccin-mocha` | [Catppuccin](https://catppuccin.com)'s Latte and Mocha flavours |
| `lofi` | `lofi` | `lofi-dark` | daisyUI's `lofi`, and its inversion |
| `nord` | `nord` | `nord-dark` | [Nord](https://www.nordtheme.com)'s Snow Storm and Polar Night |

Each card below is the family wearing a miniature app screen — `ThemePreview`, the same one
[`ThemePicker`](/docs/layout/theme-picker) draws — with the side toggle inside it. **Wear it** files
the family under both sides; **Edit** opens the [generator](/theme-generator) on the pair.

## Each card is a theme, not a picture of one

A preview is a `data-theme` attribute on a `div`:

```tsx
<div data-theme="nord">
  <YourScreen />
</div>
```

`[data-theme="nord"]` is an ordinary attribute selector — it matches an *element*, not a document —
so the theme's custom properties land on that div and inherit into everything inside it. Each theme
declares its own `color-scheme`, so a dark preview's scrollbars and form controls go dark with it.
It is also what lets a product theme a *region*: a tenant-branded panel inside a neutral app is the
same attribute in a different place.

<Callout title="The default theme binds as :root:not([data-theme])">
  Not a bare `:root`, which has the same specificity as `[data-theme="x"]`: the tie would break on
  source order. Two assertions in `themes.test.ts` hold it.
</Callout>

## Every theme clears WCAG AA, syntax included

`packages/theme/src/contrast.ts` lists the pairs a theme owes — every ink on the surface it is read
on at 4.5:1, each of the eight `--syntax-*` inks on the editor's paper and on its active line, and
the brand fill, the focus ring, a field's border and every chart slot at 3:1 against the page.
`themes.test.ts` holds all eight themes to it, and the generator warns live from the same list.

## Writing one is a form

A family is two flat blocks of about sixty declarations each, and roughly thirty decisions per
side, because the ink that follows from a fill is proposed for you. So there is a form, the
**[theme generator](/theme-generator)**, and it edits the pair together.

### The preview cannot disagree with the output

Each side's values are **inline custom properties** on its own element, and an inline declaration
block is exactly what a `[data-theme]` rule is: the same properties, the same cascade. The previews
are real tokens read by real components, and the CSS the page hands you is the style attributes
reformatted — there is no serialiser to be wrong.

### It proposes, and it does not decide

Pick a fill and its inks are proposed: `-content` sits **on** the fill (`inkFor`, daisyUI's own rule
recovered from its output, with 4.5:1 as a floor), `-foreground` is the same family read **on the
page** (`pageInk`). An ink you change stops following its fill; the link mark beside it says which
it is and takes the proposal back. The colour pickers are OKLCH — lightness, chroma, hue — because
moving perceptual lightness is the move that changes contrast without dragging the hue.

### It warns, and it does not refuse

The contrast panel lists every pair below its floor, on both sides, by token. Red is a fact, not a
veto: what checks the artefact is the guard over the shipped files.

### What it hands you

- **Theme CSS** — two blocks, each with its `@family` / `@label` header. In this repository each
  block is its own `packages/theme/themes/<name>.css`; run `pnpm --filter @kanzo-tech/theme gen`.
- **Instance config** — the same CSS plus the families offered, the default and the lock, as a
  `branding:` snippet an instance reads declaratively.
- **The link** — the whole pair in the URL fragment, deflate-compressed. A fragment never reaches a
  server, so a client's unreleased palette does not leave their machine. Links made before pairs
  still open, as the side they declared.
