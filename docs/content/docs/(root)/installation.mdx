title: Installation
description: The packages, the peers you may not need, one stylesheet and one provider.
---

<Steps>

<Step>

### Install the packages

`@kanzo-tech/ui` depends on `@kanzo-tech/theme`, so installing the first brings the second.

```npm
npm install @kanzo-tech/ui
```

</Step>

<Step>

### Install the peers

React 19 or later, plus `lucide-react` for icons.

```npm
npm install react react-dom lucide-react
```

Everything else is **optional**, and only if you import the matching subpath. Each subpath
statically re-exports its engine, so installing its peers is what buys you that subpath and
nothing else:

| Subpath | What it is | Optional peers |
| --- | --- | --- |
| [`@kanzo-tech/ui/table`](/docs/data-display/data-table) | The connected data table | `@tanstack/react-table` |
| [`@kanzo-tech/ui/analytics`](/docs/data-display/charts) | The charts, over Mosaic + DuckDB | `@uwdata/vgplot`, `@uwdata/mosaic-core`, `@uwdata/mosaic-sql`, `@duckdb/duckdb-wasm` |
| [`@kanzo-tech/ui/editor`](/docs/forms/code-editor) | The CodeMirror editors | `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/commands`, `@codemirror/search`, `@codemirror/autocomplete`, `@lezer/highlight` |

<Callout type="info">
  The base entry never imports any of them. That is deliberate — a static import of an optional
  peer from the root barrel makes `import { Button }` throw for everyone who did not install it,
  and it is why each of these has a presentational half in the root barrel and a connected half on
  the subpath. See [the engine rule](/docs/philosophy#the-engine-rule).
</Callout>

</Step>

<Step>

### If you onboard tenants, add the palette package

There is a third package, and most applications never install it.
[`@kanzo-tech/palette`](/docs/theming#colour-the-palette-document) derives a tenant's colour document —
ramps, the categorical search, the role table — and it is **authoring-time only**: the derivation
runs once at onboarding and the runtime does nothing but apply the result. It is a separate
package so that promise is structural rather than a convention.

```bash
pnpm add -D @kanzo-tech/palette
```

</Step>

<Step>

### Import the stylesheet once, at the root

```tsx title="app/layout.tsx"
import "@kanzo-tech/ui/styles.css";
```

This one sheet carries the tokens, the generated themes and every component's compiled CSS.
There is no runtime style injection, so no flash of unstyled content.

</Step>

<Step>

### Wrap the app in the provider

```tsx title="app/layout.tsx"
import { KanzoThemeProvider } from "@kanzo-tech/ui";

export default function RootLayout({ children }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <KanzoThemeProvider>{children}</KanzoThemeProvider>
      </body>
    </html>
  );
}
```

</Step>

<Step>

### Use a component

```tsx
import { Button } from "@kanzo-tech/ui";

export default function Page() {
  return <Button>Get started</Button>;
}
```

</Step>

</Steps>

## Server-side rendering

Render `themeScript()` in `<head>` so the theme attributes land before first paint, and pair it
with `cookieStorageAdapter()` so the server reads the same source the client writes. Without
both, the first frame paints with default theme and then corrects itself.

```tsx title="app/layout.tsx"
import { KanzoThemeProvider, themeScript, cookieStorageAdapter } from "@kanzo-tech/ui";

<head>
  <script dangerouslySetInnerHTML={{ __html: themeScript() }} />
</head>
<KanzoThemeProvider storage={cookieStorageAdapter()}>{children}</KanzoThemeProvider>
```

See [Theming](/docs/theming) for dark mode and the full axis list.
