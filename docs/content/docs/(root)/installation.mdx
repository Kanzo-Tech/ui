<Step>

### Install the packages

`@kanzo-tech/ui` depends on `@kanzo-tech/theme`, so installing the first brings the second.

```npm
npm install @kanzo-tech/ui
```

</Step>

<Step>

### Install the peers

React 19 or later, `lucide-react` for icons, and Tailwind CSS v4 — the library ships Tailwind
source, and your build compiles it.

```npm
npm install react react-dom lucide-react tailwindcss
```

Everything else is **optional**, and only if you import the matching subpath. Each subpath
statically re-exports its engine, so installing its peers is what buys you that subpath and
nothing else:

| Subpath | What it is | Optional peers |
| --- | --- | --- |
| [`@kanzo-tech/ui/table`](/docs/data-display/data-table) | The connected data table | `@tanstack/react-table` |
| [`@kanzo-tech/ui/analytics`](/docs/analytics) | The charts, over Mosaic + DuckDB | `@kanzo-tech/mosaic`, `@uwdata/vgplot`, `@uwdata/mosaic-plot`, `@uwdata/mosaic-core`, `@uwdata/mosaic-sql` |
| [`@kanzo-tech/ui/editor`](/docs/forms/code-editor) | The CodeMirror editors | `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/commands`, `@codemirror/search`, `@codemirror/autocomplete`, `@lezer/highlight` |

<Callout type="info">
  The base entry never imports any of them. That is deliberate — a static import of an optional
  peer from the root barrel makes `import { Button }` throw for everyone who did not install it,
  and it is why each of these has a presentational half in the root barrel and a connected half on
  the subpath. See [the engine rule](/docs/philosophy#the-engine-rule).
</Callout>

### The graph is a package, not a subpath

[`@kanzo-tech/graph`](/docs/graph) is installed separately, and the reason it is not a fourth row
above is the reason it is not in `@kanzo-tech/ui` at all: its renderer peer is **required**, not
optional, and a required WebGL dependency would change what the base library is — [the first
admission rule](/docs/philosophy#admission) excludes graphs by name.

```bash
pnpm add @kanzo-tech/graph @cosmos.gl/graph @kanzo-tech/mosaic @kanzo-tech/ui lucide-react react
```

Every peer is required: `@kanzo-tech/mosaic` is the coordinator the graph reads through and the
crossfilter it shares with the charts. The graph imports nothing of fossil's — the host attaches a
corpus with `@fossil-lang/corpus`'s `open`, its own dependency, and names the catalog to the root.

### The AI surfaces are a package too

[`@kanzo-tech/ai`](/docs/ai) is the other sibling, and it is separate for a different reason — not a
required renderer, but the barrel itself. The line is *does the component know a model exists*:
`Assist` asks one and `Chat` draws its answers, which is domain knowledge the generic vocabulary does
not carry, and a consumer who wants a `Button` must not pay for a transcript.

```bash
pnpm add @kanzo-tech/ai @kanzo-tech/llm ai @ai-sdk/react
```

The model is reached through [`@kanzo-tech/llm`](/docs/ai/llm), which has no React: `createGateway`
names a model behind a gateway, and the AI SDK is re-exported from it so a host never imports `ai`
itself. `ai` and `@ai-sdk/react` are **required** peers, installed once, because the host's agent and
these components must share one copy of the SDK's types. Neither package has an optional peer or a
subpath. Everything `ai` draws with is `@kanzo-tech/ui` and Ark, both required peers, and its
appearance is one more line in the stylesheet below — its own `@source`s, streamdown's included, and
nothing else.

### Authentication is a package that draws nothing

[`@kanzo-tech/auth`](/docs/auth) is the third sibling, and it is the one that needs none of the
above: it does not import `@kanzo-tech/ui`, it ships no component and it has no stylesheet. The
first admission rule excludes auth by name, for the reason the log-out affordance is missing from
[the sidebar](/docs/navigation/sidebar) — a library whose vocabulary every product shares should not
know what a session is.

```bash
pnpm add @kanzo-tech/auth
```

That is the whole install for a single-page application: the root barrel carries no engine, which is
what makes it the door every consumer opens. The other three each name theirs, and you install only
the one you open.

| subpath | what it is | install alongside |
| --- | --- | --- |
| `@kanzo-tech/auth/browser` | a public client with PKCE, for a SPA with no server | `oidc-client-ts` |
| `@kanzo-tech/auth/server` | the confidential client, framework-agnostic | `openid-client`, `jose` |
| `@kanzo-tech/auth/next` | App Router routes, middleware and a session reader | `next` |

The two server doors are Node's, and nothing on them reaches React —
`packages/auth/src/server.test.ts` imports them without React to say so, rather than trusting this
sentence.

</Step>


<Step>

### Import the entries into your Tailwind stylesheet

```css title="app/globals.css"
@import "tailwindcss";
@import "@kanzo-tech/ui/tailwind.css";
@import "@kanzo-tech/ai/tailwind.css"; /* only with @kanzo-tech/ai */
```

The entries are Tailwind source, not compiled CSS. `@kanzo-tech/ui`'s carries the tokens, the
generated themes, the `dark` variant, the typography plugin and the `@source` that finds its own
components; `@kanzo-tech/ai`'s adds its components and streamdown's. Your build compiles the page
once — one preflight, one utilities layer, one variant order — and your own utilities resolve
against the same tokens. Do not import `@kanzo-tech/theme/tokens.css` beside them: the entry
already does.

</Step>

<Step>

### Wrap the app in the provider

```tsx title="app/layout.tsx"
import { KanzoThemeProvider } from "@kanzo-tech/ui";

export default function RootLayout({ children }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <KanzoThemeProvider>{children}</KanzoThemeProvider>
      </body>
    </html>
  );
}
```

</Step>

<Step>

### Use a component

```tsx
import { Button } from "@kanzo-tech/ui";

export default function Page() {
  return <Button>Get started</Button>;
}
```

## Running the services

`@kanzo-tech/auth` and `@kanzo-tech/llm` each talk to a server, and both servers ship from this
repository under the same tag as the packages: [the identity service](/docs/auth/service), Keycloak
with the platform realm as code, and [the gateway](/docs/ai/gateway), LiteLLM with both aliases on
local models. A product adopting either includes the service's `compose.yml` in its own development
stack, from a checkout pinned to the release its packages came from, and registers itself — a client
and its roles, a team per tenant — with the service's Terraform module, from its own repository.

## Server-side rendering

Render `themeScript()` in `<head>` so the theme attributes land before first paint. **That one is
not optional for an SSR host**: every axis lives in browser storage, so without it the server paints
the defaults and the client re-skins on hydration — a flash, plus a hydration mismatch in any
control whose markup depends on the resolved appearance.

`cookieStorageAdapter()` is the optional half. It lets the *server* read the same source the client
writes, so the rendered `<html>` already carries the attributes rather than acquiring them a moment
later. Colour is not a reason to add it: every theme ships in the page at once and the choice is an
attribute, so the script applies it like any other axis.

```tsx title="app/layout.tsx"
import { KanzoThemeProvider, themeScript, cookieStorageAdapter } from "@kanzo-tech/ui";

<head>
  <script dangerouslySetInnerHTML={{ __html: themeScript() }} />
</head>
<KanzoThemeProvider storage={cookieStorageAdapter()}>{children}</KanzoThemeProvider>
```

See [Theming](/docs/theming) for dark mode and the full axis list.
