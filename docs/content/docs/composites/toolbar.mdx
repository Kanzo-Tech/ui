## Usage

```tsx
import { Toolbar, ToolbarStart, ToolbarCenter, ToolbarEnd } from "@kanzo-tech/ui";
```

```tsx
<Toolbar>
  <ToolbarStart>{/* back button, breadcrumbs, path */}</ToolbarStart>
  <ToolbarCenter>{/* optional centred label */}</ToolbarCenter>
  <ToolbarEnd>{/* status text, then controls */}</ToolbarEnd>
</Toolbar>
```

Toolbar mirrors `StatusBar` — same compact IDE aesthetic, same
card surface, same small type — but sits at the *top* of a view and is bordered below, so the
two frame the canvas between them. It is a `role="toolbar"` landmark and every region is a
slot, so it carries no domain of its own.

Put navigation here rather than floating it over the canvas: in the chrome it stays legible,
stays in the tab order, and never covers the content it would take you away from.

## Anatomy

```text
Toolbar
├── ToolbarStart    (takes the free space and truncates)
├── ToolbarCenter
└── ToolbarEnd
```

Regions are named `Start`/`End`, not `Left`/`Right`: they follow the writing direction, so the
strip mirrors in RTL without a second layout.

## API Reference

### Toolbar

Renders a `div` with `role="toolbar"`; takes its props.

| Prop | Type | Default |
| --- | --- | --- |
| `aria-label` | `string` | `"Toolbar"` |

### ToolbarStart / ToolbarCenter / ToolbarEnd

Each renders a `div` and takes its props; none carries options of its own.
