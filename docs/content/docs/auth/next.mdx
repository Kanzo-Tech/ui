```ts
import { kanzoAuth } from "@kanzo-tech/auth/next";
```

One name over [the server reader](/docs/auth/server), and the files an App Router product already has.
The application sits behind the edge — oauth2-proxy, [extended by the
application](/docs/auth/service#the-sessions-edge) — which signs the person in, keeps the session and
forwards the access token; nothing here signs anyone in.

```ts title="lib/auth.ts"
import { kanzoAuth } from "@kanzo-tech/auth/next";

export const auth = kanzoAuth(async () => ({
  issuer: "https://id.example/realms/kanzo",
  clientId: "board",
  jwks: "http://keycloak:8080/realms/kanzo/protocol/openid-connect/certs",
  organization: ({ url }) => url.hostname.split(".")[0],
  apis: {
    "/api": { target: (organization) => `http://${organization}-api:8080` },
  },
}));
```

```ts title="proxy.ts"
export const proxy = (request: NextRequest) => auth.proxy(request);
export const config = { matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"] };
```

```ts title="app/api/[...path]/route.ts"
export const { GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS } = auth.api;
```

```tsx title="app/layout.tsx"
<AuthProvider session={await auth.session()}>{children}</AuthProvider>
```

And in any server component:

```tsx title="app/(signed-in)/layout.tsx"
const session = await auth.session({ required: true });
if (!can(session, "reader")) forbidden();
```

`kanzoAuth` returns a `KanzoAuth`: `session`, `proxy` and `api`, over one config and one session
reader. `can` comes from the root barrel, exactly as `Gate` asks in the browser.

<Callout type="info">
**There is no `requireRole`.** It would have added no new evaluation of a role — only a *throw* —
and which throw (`forbidden()`, a redirect, a rendered explanation) is a product's answer rather
than a library's. `packages/auth/src/next.test.ts` is what keeps it absent, rather than this
sentence.
</Callout>

## Bound on the first request

The config is a function, and it may be async. `next build` imports every module with no
configuration in the environment, so nothing is read at import: the function runs on the first
request that needs it, and the instance it builds is kept. **A failure is not kept**: a deployment
that started before its configuration was ready recovers on the next request rather than remembering
the fault for the life of the process. `api` is a plain handler object that exists at import time,
which is what `export const { GET, … } = auth.api` needs.

## `session()` in a server component

```ts
const session = await auth.session();                    // Session | null
const session = await auth.session({ required: true });  // Session, or a redirect
```

It reads the forwarded token through `next/headers`, verifies it against the realm's keys
([Server](/docs/auth/server)), and is memoised per request through React's `cache`, so a layout, a
breadcrumb and a menu asking in one render verify it once. `null` means the edge forwarded no token.

`{ required: true }` is AuthKit's `ensureSignedIn`. With no token it redirects to the edge's
`sign_in`, carrying the path and query the proxy forwarded; the edge signs a person in before the page
renders, so this is a path the edge lets through, or an application reached without its edge. A token
that does not verify, or keys that could not be fetched, redirect to `problemPage` with the code,
never to sign-in: the edge holds a session and would forward the same token. Without `required`, a
failure is thrown as the `Problem`, for a page that renders through one and reads it itself.

## `proxy`

The edge in front of the application decided who may reach it; `proxy` behind it decides nothing
about the session and lets every request through. It does two things.

### The URL, forwarded

Every request leaves the proxy with `x-kanzo-url` set to the URL the browser addressed — AuthKit's
`x-url`, read from `X-Forwarded-Host` and `X-Forwarded-Proto` before the address Next listens on —
after every incoming `x-kanzo-*` header is deleted, so a browser cannot choose what a server component
reads there. `session({ required: true })` signs in back to it, and the tenant resolver reads it. Extra
request headers a product needs on the page go in the second argument, `auth.proxy(request, { headers })`.

### The CSP nonce

Give `kanzoAuth` the policy as `csp`, and `proxy` draws 128 random bits per request and names them:

```ts title="lib/auth.ts"
kanzoAuth(async () => ({
  /* … */
  csp: {
    "default-src": ["'self'"],
    "script-src": ["'wasm-unsafe-eval'"], // your extras; the nonce and 'strict-dynamic' are added
    "worker-src": ["'self'"],
    "connect-src": ["'self'"],
  },
}));
```

The `script-src` it sends is `'nonce-…' 'strict-dynamic'` followed by your sources, never
`'unsafe-inline'` (which throws when the config is read). The policy rides on the request the page
sees, which is the header Next reads to put the nonce on its own scripts, and on the response; a
server component that needs the nonce reads `x-nonce` from `headers()`. A page that carries a nonce
renders per request, and a browser without CSP Level 3 does not run its scripts.

## Tenancy

`organization` resolves the tenant a request addresses: a hostname's first label, a path segment,
a cookie, or one fixed alias for a deployment per tenant.

```ts
organization: ({ url, headers, cookies }) => url.hostname.split(".")[0]
```

It is handed a `TenantRequest` — `{ url, headers, cookies }`, exported from `@kanzo-tech/auth/next`
for a resolver written as a function of its own — built the same way wherever it runs: the forwarder
from its request, a server component from `host` and the `x-kanzo-url` the proxy forwarded. Its answer
is `Session.organization`, and it is the organization [`can`](/docs/auth/roles) asks inside by default.
The tenant is resolved per request and never stored, which is what lets two tabs sit in two
organizations at once.

## `api`

`apis` names each resource server the application calls by the path it is mounted on, and a request
under a mount is forwarded to its `target` with **the token the edge forwarded as its bearer**. A
request is forwarded by the longest mount it is under, so `/api/search` is the search API and
`/api/anything-else` is the board's.

There is no exchange. The edge asks for the API's scope at sign-in, so the token already names the
API in `aud` ([Keycloak](/docs/auth/keycloak#the-apis-an-application-calls)). The token is verified
before it is forwarded — a header that did not come through the edge is refused here and never
reaches an API — and the API verifies it again itself.

Ninety lines every product writes the same way, and one of them is load-bearing in a way that does
not look it: **the `cookie` header is not forwarded**. Leave it on and the resource server receives
the edge's session beside the bearer token, a second credential. The edge's `X-Forwarded-*` headers
are not forwarded either: the token travels once, as the bearer.

What else it does, none of which is a product's idea of its own domain: strips the hop-by-hop
headers, strips `Origin` and the `Sec-Fetch-*` headers — what the browser says about the page behind
*its* request, which the same-site check has read — forwards the body as a stream with
`duplex: "half"` so an upload is never read into memory and an SSE stream is never buffered until it
ends, sets `redirect: "manual"` so a `Location` from the upstream cannot send the bearer token to
whatever host it names, drops `set-cookie` from the answer, and drops `content-encoding` and
`content-length` with it.

`target` may be a function of the organization the request addresses — the same answer
`organization` gives — for one application in front of a resource server per tenant. That is
Keycloak's Organizations model: **one client shared by every organization**, with the tenant in the
token. The token names every organization the person belongs to, so the forwarder refuses a request
for one it does not name before the API is asked, and each API authorises inside its own
organization's entry ([why](/docs/design/auth#one-token-naming-the-applications-api)). A request
that addresses no organization — a bare host — gets `undefined` from the function, and `api`
answers it 404.

It answers a problem — RFC 9457, with the registry's code — for a credential: **401** when the edge
forwarded no token (`session/absent`) or one that does not verify (`token/refused`), **403** when the
person is not a member of the organization the request addresses (`organization/denied`), **502** or
**504** when the realm's keys could not be fetched (`idp/unreachable`, `idp/silent`), **502** when the
API itself does not answer (`api/unreachable`): the connection is refused, its name does not resolve,
it resets before a status line — and **504** when it connected and sent no headers within 25 s
(`api/silent`). An API that answers, whatever the status, has answered, and its answer is passed
through as it came. Without a body: **403** when the request is not same-site — a request with
neither `Sec-Fetch-Site` nor `Origin` included — **400** for a path under no mount, and **404** when
`kanzoAuth` was given no `apis`.

<Callout type="info">
**List the API's mount as an API route at the edge** (`OAUTH2_PROXY_API_ROUTES`), so a `fetch` from a
page whose session ended is answered 401 by the edge rather than redirected to Keycloak, which a
`fetch` cannot follow.
</Callout>

## Where each mechanism comes from

Nothing here is invented; each piece is a reference system's answer or a standard's.

| Mechanism | Reference |
| --- | --- |
| Tokens on a server, a cookie in the browser | RFC 10017, Backend For Frontend, run by oauth2-proxy |
| The access token verified by whoever receives it | RFC 9068 |
| The URL forwarded to the page; `required` | WorkOS AuthKit, `x-url`, `ensureSignedIn` |
| `Origin` and `Sec-Fetch-*` end at the application | RFC 6454 §7; W3C Fetch Metadata |
| A refusal's body | RFC 9457, Problem Details for HTTP APIs |

## API Reference

### `kanzoAuth`

`kanzoAuth(config: KanzoAuthConfig | (() => KanzoAuthConfig | Promise<KanzoAuthConfig>)): KanzoAuth`.

`KanzoAuthConfig` is [`SessionReaderConfig`](/docs/auth/server#sessionreader) — `issuer`, `clientId`,
`jwks` — plus:

| Prop | Type | Default |
| --- | --- | --- |
| `organization` | `(request: TenantRequest) => string \| undefined \| Promise<…>` | no current tenant |
| `prefix` | `string`, where the edge's `sign_in` and `sign_out` live (`OAUTH2_PROXY_PROXY_PREFIX`) | `/api/auth` |
| `problemPage` | `string` | `/auth/problem` |
| `csp` | `Record<string, readonly string[]>`, directive to sources; `proxy` adds the nonce and `'strict-dynamic'` to `script-src` | none; no policy is sent |
| `apis` | `Record<string, { target: string \| ((organization: string \| undefined) => string \| undefined) }>`, by mount | none; `api` answers 404 |

### `KanzoAuth`

| Member | Type |
| --- | --- |
| `session` | `() => Promise<Session \| null>`, and `({ required: true }) => Promise<Session>` |
| `proxy` | `(request: NextRequest, options?: { headers?: HeadersInit }) => Promise<NextResponse>` |
| `api` | `{ GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS }`, each a web `Request` in and a web `Response` out |
