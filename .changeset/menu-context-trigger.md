**There was never a context menu component. `simples/context-menu.tsx` is deleted, and the one part that was real is now `MenuContextTrigger` in `menu.tsx`. Breaking, with no aliases.**

The file exported ten values in 68 lines. Nine of them were `data-slot` renames of `Menu`'s own parts and nothing else — `ContextMenuItem` was literally `<MenuItem data-slot="context-menu-item" {...props} />`, and the same for `ContextMenuContent`, `Group`, `Separator`, `Sub`, `SubContent`, `SubTrigger`, `Shortcut` and the root, which rendered `<Menu data-slot="context-menu">`. The tenth, `ContextMenuTrigger`, wrapped Ark's `Menu.ContextTrigger` and added `cursor-default`. That one is a real API — right-click at the pointer instead of anchoring to a control — so it survives under Ark's own name for the part, `MenuContextTrigger`, sitting beside `MenuTrigger` in the file that owns the machine.

DESIGN.md's ladder reserves a new component for new **behaviour** or new **DOM structure**; rung 2 is "composition + `data-*`". This family was paying ten exports for rung 2, and the docs had already noticed: there is no `context-menu.mdx` and never was one. The context menu was documented inside the Menu page, under a `<Callout>` that promises "one menu, two triggers" — which was aspirational while a parallel `ContextMenu*` vocabulary existed, and is now the literal API.

`useContextMenu` goes with it. It was `useMenuContext` re-exported under a second name, which `menu.tsx` already re-exports as `useMenu`; it had zero consumers, and two names for one hook is exactly the tax this refactor is paying off.

**The slot is `menu-context-trigger`, not `context-menu-trigger`.** Every part in the file mirrors its export name into `data-slot` in kebab-case, and that correspondence is what makes the attribute usable as a selector without reading the source. Keeping `context-menu-trigger` would have left the last inhabitant of a `context-menu-*` namespace that no longer has any other members — a selector prefix implying a family of parts that a caller would then look for and not find. `cursor-default` stays, and stays load-bearing: the trigger wraps a *region*, and the region must not read as a link or a button, because the affordance is the right-click and not the cursor.

**No back-compat aliases.** The package is unpublished and nothing outside this repo consumes it, so a clean break costs one find-and-replace today; an alias layer would be permanent, and it would re-create the exact ambiguity — two names for one part — that the deletion exists to remove. `ContextMenu` → `Menu`, `ContextMenuTrigger` → `MenuContextTrigger`, every other `ContextMenuX` → `MenuX`.

The two examples moved from `docs/examples/context-menu/` into `docs/examples/menu/` as `example-context-trigger` and `example-context-submenu`, because the examples directory is keyed to the page slug and there is no `context-menu` page for it to be keyed to. The Menu page's anatomy now shows `MenuTrigger` and `MenuContextTrigger` as the one-or-the-other they are, the API reference documents them together, and the old "ContextMenu parts" table — which existed only to say that each part forwarded to its counterpart unchanged — is replaced by the reason the parts are gone. `menu.test.tsx` is new: a right-click opens the menu, the trigger carries its slot and its cursor, the opened tree contains the plain `menu-*` slots with no `context-menu-*` survivor, and the click-to-open `MenuTrigger` is unaffected.

Two stale claims elsewhere were corrected rather than inherited. `ListboxShortcut` was rejected as "a fourth `data-slot` rename of `MenuShortcut`'s span — after `ContextMenuShortcut` and `CommandShortcut`"; with `ContextMenuShortcut` gone it would be a third, after `CommandShortcut`, in both the comment and the Listbox page. And the theming docs' list of Ark overlays that portal into `document.body` named ContextMenu alongside Menu; it is one entry now.
