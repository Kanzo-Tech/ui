One `Proposal`, the Task's, for a field, a list and a chat. `Assist` asks for its candidates through `propose` and reports each as a `Proposal<string>`: `value` is the text, and `target` is where it lands — `{ insert }` at the caret for a continuation, `{ replace }` over the value for a candidate, `{ add }` for a new tag — with `rationale` the chip's tooltip. `Chat` takes a Task's offers whole and **sends a proposal's value, never its words**: a string as the message's text, anything else through `message` — `<Chat message={askEdit} proposals={offers} />` sends Ask's spec, which the chat asks as it is, so a starter question is not re-asked of the model. `askOffers` returns the Task's `Proposal<AskSpec>[]`. **Breaking:** `Proposal` is imported from `@kanzo-tech/ai/task`, not `@kanzo-tech/ai`; on an `AssistEvent`'s `proposal`, `text` is `value` and `range` is `target`. Pass `Chat` the proposals `propose` or `askOffers` answered as they are, not mapped to `{ text }`, with `message={askEdit}` for Ask's; a fixed list of questions is `Proposal<string>`s. `askOffers` no longer returns `{ text, spec }` — `questionOf(p.value)` is the text, `p.value` the spec.
