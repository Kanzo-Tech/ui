**A measurement of all 733 exported values, and the five things it changed.** 139 were referenced nowhere in the repo; 122 appeared in exactly one `docs/examples/<slug>/` directory and nowhere else — the page proving the part exists, not the second call site admission rule 2 asks for.

**Two components that were one, again.** `CardRadioGroup` was rung-1 layout plus an `options: CardRadioOption[]` array over a compound that already existed: `RadioGroupCard` is `radio-group.tsx`'s own item styled off `data-[state=checked]`, with a comment saying exactly that. It held no state and added no DOM semantics. The grid it did own is real work and moved onto the primitive as `columns` on `RadioGroup` — `"auto"` for a track function, a number pinned through a `--columns` custom property so a caller can override it per breakpoint (`columns={1} className="sm:[--columns:2]"`), which an attribute could not. The library had already argued against the record-of-`ReactNode`s shape in writing, in `SidebarIdentity`, and won.

`SectionNav` rendered `SidebarNav`'s exact tree — `<nav>` → `SidebarGroup` → `SidebarMenu` → `SidebarMenuButton asChild` → an injected `Link` — from a different data shape. The one real difference was where routing knowledge lives: a per-item `isActive` against a single `activePath` derived by prefix. That is a genuine second opinion, not an accident, so it survives as a prop rather than as a component: `SidebarNav` now takes either. Both models are covered by tests, along with the collapsible sub-items and the mobile-drawer close that only the surviving component had.

**Renames nobody rendered.** `AlertDialogTitle`, `AlertDialogDescription`, `SheetTitle`, `SheetDescription`, `CommandDialogTrigger`, `CommandGroupLabel`, `TourFooter`, `TourBody` and `MenuArrow` were each `(props) => <OtherThing data-slot="…" {...props} />` over another component's part, with no renderer anywhere — the same shape as the ten `ContextMenu*` exports, smaller. `SkeletonCircle` and `SkeletonText` went too: nothing referenced them, not even their own file. `AlertAction` was kept instead of deleted — it is a real slot in an alert's anatomy rather than a rename of one, so it got the example it was missing.

The care this needed is worth recording, because the naive version of it breaks four components: 69 exports have no *export* consumer only because their own root renders them. `SheetOverlay` and `SheetPositioner` sit in the same file as the two deletions above and are load-bearing; so are `TourPositioner`, `TourOverlay`, `TourSpotlight` and `ClipboardIndicator`. `ProgressTrack` is the ideal case, not a defect — `progress.mdx` documents that you never place it yourself.

**Thirteen `tv()` recipes are internal again.** An exported variant object freezes a class list as public API; these had no importer at all. The exceptions stay because a *different* module needs them, and one of those nearly went in the sweep: `statusVariants` reads as "used only by its own file" and is imported by `avatar.tsx` for `VariantProps<typeof statusVariants>` — a type-position import that still requires the value to be exported. A test now pins the whole set, both halves.

**`/analytics` re-exports what consumers actually reach for.** The list carried a stated purpose — "so a consumer writes a whole chart without a direct `@uwdata` import" — and did not deliver it: eight entries had no consumer while examples imported `axisX`, `yRange` and eleven mosaic-sql/mosaic-core names directly. It is now drawn on one rule: a set is re-exported when it is **closed and named**, and stays a direct import when it is open. So `MosaicClient`, `makeClient` and the five `clause*` builders arrive — the set a custom Mosaic client needs — while vgplot's ~250 plot attributes stay a direct import, because `ChartRoot`'s `attributes` takes them raw and taking them raw is what an escape hatch is. `coordinator`, `Fixed`, `from` and `plot` are gone; the aggregates stay, judged on vocabulary coverage rather than today's count, the same argument that legitimately keeps the marks no example draws.

**Two adoption gaps closed, which is the opposite move.** `ChartStat` and `ChartColorLegend` each had a doc block, a test and a documented reason to exist — and no renderer, while their twins `StatTile` and `ChartLegend` had 3 and 12 consumers. Both now have the example that shows what the pair is for. DESIGN.md's own line about `field.tsx` applies: the highest-value move was adoption, not design.

**And a comment that claimed something untrue.** `chart-interactors.tsx` said of its six `ChartPick*`/`ChartBrush*` aliases that "the docs teach these". Zero mentions existed in any `.mdx`, while both spellings ran side by side in examples and a showcase — sometimes in one file. The pairing is now a table under "Interactors" in `charts.mdx`, and the comment says what is true plus the rule that keeps it true.
