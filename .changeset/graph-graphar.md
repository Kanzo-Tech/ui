**Breaking:** `GraphRoot`, `readJoinGraph` and every part read an Apache GraphAr graph attached by `@kanzo-tech/graphar-duckdb`'s `attachGraph`, not a `fossil/1` corpus attached by `@fossil-lang/corpus`'s `attach`. Attach the graph with `attachGraph(engine, name, resolve, { entry: "fossil.graph.yml" })` and pass the same `name` as `from`; a corpus attached by `@fossil-lang/corpus` no longer reads (its `fossil_tables` are not looked for). The graph reads `graphar_vertex_types`, `graphar_edge_types`, `graphar_properties`, `graphar_chunks` and a view per type — needs `@kanzo-tech/graphar-duckdb` with `graphar_chunks` (Kanzo-Tech/graphar #4) — and still imports nothing of the package that attached them.

What you see changes where GraphAr states less than fossil's manifest did:

- `dense_id` is still every vertex's id, `0 … V − 1`, and still what a pick and a `clauseSemiJoin` name — it is now the graph's own, computed from GraphAr's per-type `_graphArVertexIndex` in the graph document's order of the types. Read ids from the join graph's type tables (`readJoinGraph(…).types[i].table`), not from `"<name>"."<type>"`, whose rows carry GraphAr's per-type index. An edge type's `src` and `dst` are global ids there too.
- Every vertex type is drawn. Its identity is its primary key, or its id where it has none. A multi-valued property is a `list` property of the type that owns it, not a type of its own: the inspector shows its values and a search can name it (`nickname:ana`), but it is not offered as a position, a group or a timeline column, nor as a field of a dashboard, `RelationPicker` or Ask — a path such as `laureate.nickname` no longer exists.
- The join graph's columns carry their DuckDB type, `nullable`, a `role` for the two keys (`address` for `dense_id`, `identity` for the primary key — also each type's `candidateKeys`), and the writer's counts (`stats`: nulls, distinct values, extent, commonest values), read from each chunk's Parquet footer — `fossil:stats` in its `key_value_metadata` and the row groups' `Statistics`. A column is counted when one chunk of its type states it; a graph whose chunks state none has none, and `useFieldStats` reads its relation with one `SUMMARIZE`. They carry no `iri`, `termType`, `datatype` or annotations: a field is called by its name, and a year stored as an integer is a number — the timeline offers GraphAr `date` and `timestamp` columns only.
- `GraphState.structure` changed shape: a type's columns are `{ type, primary, nullable, stats }`, each type and edge has a `table` (its rows under global ids), and `key`, `properties`, `candidateKeys`, `iri`, `annotations`, `sourceKey` and `destinationKey` are gone.
