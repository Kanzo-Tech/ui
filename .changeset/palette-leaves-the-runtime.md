**The colour derivation leaves the runtime package.** New `@kanzo-tech/palette` owns `ramp`,
`palette-check`, `derive-scheme`, `derive-palette`, `roles`, `palette-document`, `compile` and
`seeds`; `@kanzo-tech/theme` keeps the stylesheets, the four non-colour axes and the preference
types, and depends on `palette` as a **devDependency** only.

This is not an optimisation. The design's second decision is *"derivation has no first-paint
budget; the runtime only applies"*, and that was a promise anyone could break by accident while a
0.2–7.4 s categorical search sat in the package a browser imports. Out of the dependency graph it
now *cannot* be imported, rather than merely should not — the same move as "generation has no
regimes, only reporting does": turn the principle into something the code enforces instead of
something a reviewer remembers. `packages/theme/src/boundary.test.ts` fails if `palette` ever
appears in `dependencies`, if anything outside the tests imports it, or if the entry re-exports the
derivation; `pnpm smoke` asserts the same against a real installed tree.

`packages/theme/src` goes from 6,075 lines to 335, and 132 of those are the entry — most of it the
note recording why each survivor is there. 5,450 lines moved across verbatim.

**The tables the derivation reads moved with it.** `theme-data.json` was twelve keys, of which
eight — `ramps`, `baseSwatches`, `schemes`, `defaultScheme`, `palettes`, `seeds`, `syntaxRoles`,
`statusInk` — are *inputs to the maths*, and shipping them beside a stylesheet a browser loads was
half of the same defect. They are now `packages/palette/palette-data.json`, generated by
`scripts/gen-data.mjs` (split out of `gen-theme.mjs`, byte-identical output). `theme-data.json`
keeps `radii`, `fonts`, `monoFonts` and `densities` — the four axes and nothing else — and drops
from 9,104 bytes to 1,099. The theme's built entry is 1.59 kB where it bundled 45.59 kB.

The dependency runs one way, which is why the data moved rather than being reached back for: had
`palette` kept reading `@kanzo-tech/theme/theme-data.json`, the two packages would have been a
cycle, and a cycle is a structural statement that the boundary is wrong.

### Moved exports

`derivePalette`, `compile`, `deriveRamp`, `checkRamp`, `checkScheme`, `deriveScheme`,
`deriveOrderedScheme`, `deriveSchemeColors`, `resolveRoles`, `ROLES`, `OBLIGATIONS`, `oklch`,
`contrastRatio`, `deltaE`, `PALETTE_SEEDS`, `KANZO_ID`, `seedInput`, `BASE16_SLOTS` and every
derivation type now come from `@kanzo-tech/palette`. `themeData` stays in `@kanzo-tech/theme` but
carries only the four axis tables; `paletteData` is its counterpart on the derivation side.

### CHART_SLOTS is declared in both, and trusted in neither

`packages/ui/src/charts/theme.ts` resolves `var(--chart-N)` off the live cascade and needs the
count, in a browser, where the derivation cannot be reached. So `@kanzo-tech/theme` declares
`CHART_SLOTS` as what it is there — a fact about the **sheet**, how many `--chart-*` properties it
declares — and `@kanzo-tech/palette` declares it as what it is there: how many the role table
emits. Neither copy is authoritative. `boundary.test.ts` counts the `--chart-N` declarations in
the shipped `tokens.css` and holds both against that, so the constants answer to the artefact
rather than to each other. `packages/ui` is unchanged.

`--chart-capacity` still travels down the cascade for the count that *can* vary — how many slots
name a real category — and `categoricalCapacity()` still reads it. The two are different facts:
capacity is a property of one tenant's set, `CHART_SLOTS` is a property of the stylesheet's
vocabulary, and a pure `categoricalColor(i)` with no DOM to read has to clamp against the latter.
